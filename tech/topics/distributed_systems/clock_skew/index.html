Reconcile clocks across regions

Absolute wall clocks lie across regions — ordering and TTLs need a better story than Date.now().

60-minute agenda

How I'd open the discussion

The core issue is that wall clocks across machines — even NTP-synchronized ones — can disagree by milliseconds to hundreds of milliseconds. That sounds small until you realize that 'which write happened last' determines who wins in a last-writer-wins conflict resolution scheme. A 50 ms skew can flip the winner. And TTLs based on wall time can expire early on one machine and late on another.

There are three response levels. First, for ordering: use logical clocks (Lamport or vector) that track causality rather than physical time. If A caused B, the logical clock guarantees A < B regardless of wall-clock skew. Second, for systems that need both ordering and human-readable timestamps: hybrid logical clocks (HLC) combine physical time with a logical counter. The physical component stays close to wall time; the logical component breaks ties.

Third, for the strongest guarantee: Google's TrueTime exposes a confidence interval [earliest, latest] instead of a single timestamp. Spanner's commit-wait ensures that if transaction T1 commits before T2 starts, T1's timestamp < T2's timestamp — but you pay a latency cost equal to the uncertainty interval (typically 7 ms with atomic clocks and GPS receivers).

Functional requirements

hlc_now()

Returns a hybrid logical clock timestamp: (physical_ms, logical_counter, node_id).

hlc_send(local_hlc)

Advances the clock and returns the timestamp to attach to the outgoing message.

hlc_receive(local_hlc, msg_hlc)

Merges the received timestamp with local clock, advances counter.

compare(ts1, ts2)

Returns -1, 0, or 1 — total order over HLC timestamps.

Non-functional / rough numbers

Clock drift

HLC physical component stays within max_drift (e.g., 500 ms) of wall time.

Causal consistency

If event A causally precedes B, hlc(A) < hlc(B) guaranteed.

Ordering accuracy

Concurrent events from different nodes ordered deterministically by node_id tiebreaker.

Latency

HLC operations complete in < 1 μs — no network calls.

Approach / design notes

Wall clocks are unreliable across machines. NTP keeps clocks within a few milliseconds in a data center, but cross-region skew can be 50–200 ms. A system that uses timestamps for ordering (like last-writer-wins in Cassandra) can silently lose writes when the 'earlier' write has a higher timestamp due to clock skew on its node.

Lamport clocks solve causal ordering: each node maintains a counter. On local event, increment. On send, increment and attach. On receive, set counter = max(local, received) + 1. If A→B (A causally precedes B), then L(A) < L(B). But Lamport clocks don't track physical time — they can drift far from wall time, making them useless for TTLs or human-readable logs.

Hybrid Logical Clocks (HLC) fix this. The timestamp is (physical_ms, logical_counter). On a local event: if wall_time > physical_ms, set physical_ms = wall_time and reset logical to 0. Otherwise increment logical. On receive: set physical_ms = max(local_physical, msg_physical, wall_time). If physical_ms advanced, reset logical. Otherwise logical = max(local_logical, msg_logical) + 1. The physical component stays close to wall time (bounded by max_drift), and the logical component provides sub-millisecond causal ordering.

For the strongest guarantees, Google's TrueTime uses GPS receivers and atomic clocks to provide a time interval [earliest, latest] with uncertainty ~7 ms. Spanner's commit-wait: after assigning a commit timestamp, the transaction waits until TrueTime.after(commit_ts) returns true. This guarantees that any transaction that starts after the commit sees the committed data — external consistency. The cost is ~7 ms of added latency per commit.

In stream processing, the distinction is event-time (when the event happened at the source) vs processing-time (when the system processes it). Watermarks track progress in event-time: 'we believe all events with timestamp < W have arrived.' Late data arrives after the watermark passes — you handle it with allowed-lateness windows or side outputs.

Deep dive (spend 15–25 minutes here)

Concrete HLC walkthrough with three nodes (A, B, C), all starting at physical=1000, logical=0.

Step 1: Node A has a local event at wall_time=1001. Since 1001 > physical(1000), update physical=1001, logical=0. A's HLC = (1001, 0, A).

Step 2: Node A sends a message to Node B with timestamp (1001, 0, A). Node B receives it at wall_time=1000 (B's clock is behind). Node B computes: max(local_physical=1000, msg_physical=1001, wall_time=1000) = 1001. Since 1001 > local_physical, update physical=1001, logical=0. But wait — msg_physical is also 1001, so we need logical = max(local_logical=0, msg_logical=0) + 1 = 1. B's HLC = (1001, 1, B). Ordering: (1001,0,A) < (1001,1,B) — correct, A's send happened before B's receive.

Step 3: Node C has a local event at wall_time=1003 (C's clock jumped). Since 1003 > physical(1000), update physical=1003, logical=0. C's HLC = (1003, 0, C). This event is concurrent with B's — no causal relationship. The HLC ordering (1001,1,B) < (1003,0,C) happens to match wall time, which is a nice property of HLC: for concurrent events, the ordering approximates real time.

Drift guard: if wall_time is dramatically behind (e.g., NTP adjustment), physical_ms could advance far beyond wall time via received messages. HLC implementations cap this: if physical_ms − wall_time > max_drift (say 500 ms), the node refuses to advance and raises an alert. This prevents logical clocks from drifting into the future indefinitely.

TrueTime commit-wait trace: Spanner assigns commit timestamp T = TT.now().latest. Then it waits until TT.after(T) returns true — meaning T is definitely in the past. With 7 ms uncertainty, the wait is at most 14 ms (worst case: sampled at the start of an interval). After the wait, any future TT.now().earliest on any machine is > T, so any subsequent transaction sees the commit.

Hybrid Logical Clock with drift guard

import time

class HybridLogicalClock:
    def __init__(self, node_id: str, max_drift_ms: int = 500):
        self.node_id = node_id
        self.physical_ms = 0
        self.logical = 0
        self.max_drift_ms = max_drift_ms

    def _wall_ms(self) -> int:
        return int(time.time() * 1000)

    def now(self) -> tuple:
        wall = self._wall_ms()
        if wall > self.physical_ms:
            self.physical_ms = wall
            self.logical = 0
        else:
            self.logical += 1
        return (self.physical_ms, self.logical, self.node_id)

    def send(self) -> tuple:
        return self.now()

    def receive(self, msg_physical: int, msg_logical: int) -> tuple:
        wall = self._wall_ms()
        old_physical = self.physical_ms
        self.physical_ms = max(old_physical, msg_physical, wall)

        if self.physical_ms - wall > self.max_drift_ms:
            raise RuntimeError(
                f'HLC drift {self.physical_ms - wall} ms exceeds max {self.max_drift_ms} ms'
            )

        if self.physical_ms == old_physical == msg_physical:
            self.logical = max(self.logical, msg_logical) + 1
        elif self.physical_ms == old_physical:
            self.logical += 1
        elif self.physical_ms == msg_physical:
            self.logical = msg_logical + 1
        else:
            self.logical = 0

        return (self.physical_ms, self.logical, self.node_id)

    @staticmethod
    def compare(ts1: tuple, ts2: tuple) -> int:
        for a, b in zip(ts1, ts2):
            if a < b:
                return -1
            if a > b:
                return 1
        return 0
use std::cmp::Ordering;
use std::time::{SystemTime, UNIX_EPOCH};

#[derive(Debug, Clone, PartialEq, Eq, PartialOrd, Ord)]
pub struct HLCTimestamp {
    pub physical_ms: u64,
    pub logical: u64,
    pub node_id: String,
}

pub struct HybridLogicalClock {
    node_id: String,
    physical_ms: u64,
    logical: u64,
    max_drift_ms: u64,
}

impl HybridLogicalClock {
    pub fn new(node_id: &str, max_drift_ms: u64) -> Self {
        Self { node_id: node_id.into(), physical_ms: 0, logical: 0, max_drift_ms }
    }

    fn wall_ms() -> u64 {
        SystemTime::now()
            .duration_since(UNIX_EPOCH)
            .unwrap()
            .as_millis() as u64
    }

    pub fn now(&mut self) -> HLCTimestamp {
        let wall = Self::wall_ms();
        if wall > self.physical_ms {
            self.physical_ms = wall;
            self.logical = 0;
        } else {
            self.logical += 1;
        }
        HLCTimestamp {
            physical_ms: self.physical_ms,
            logical: self.logical,
            node_id: self.node_id.clone(),
        }
    }

    pub fn send(&mut self) -> HLCTimestamp { self.now() }

    pub fn receive(&mut self, msg_phys: u64, msg_log: u64) -> HLCTimestamp {
        let wall = Self::wall_ms();
        let old_phys = self.physical_ms;
        self.physical_ms = old_phys.max(msg_phys).max(wall);

        if self.physical_ms.saturating_sub(wall) > self.max_drift_ms {
            panic!(
                "HLC drift {} ms exceeds max {} ms",
                self.physical_ms - wall, self.max_drift_ms
            );
        }

        if self.physical_ms == old_phys && old_phys == msg_phys {
            self.logical = self.logical.max(msg_log) + 1;
        } else if self.physical_ms == old_phys {
            self.logical += 1;
        } else if self.physical_ms == msg_phys {
            self.logical = msg_log + 1;
        } else {
            self.logical = 0;
        }

        HLCTimestamp {
            physical_ms: self.physical_ms,
            logical: self.logical,
            node_id: self.node_id.clone(),
        }
    }

    pub fn compare(a: &HLCTimestamp, b: &HLCTimestamp) -> Ordering {
        a.cmp(b) // derives lexicographic (physical, logical, node_id) order
    }
}

struct HLCTimestamp {
    uint64_t physicalMs;
    uint64_t logical;
    std::string nodeId;

    bool operator>(const HLCTimestamp &o) const {
        return std::tie(physicalMs, logical, nodeId)
             > std::tie(o.physicalMs, o.logical, o.nodeId);
    }
};

static uint64_t wallMs() {
    struct timeval tv;
    gettimeofday(&tv, nullptr);
    return (uint64_t)tv.tv_sec * 1000 + tv.tv_usec / 1000;
}

- (HLCTimestamp)now {
    uint64_t wall = wallMs();
    if (wall > _physicalMs) {
        _physicalMs = wall;
        _logical    = 0;
    } else {
        _logical += 1;
    }
    return {_physicalMs, _logical, _nodeId};
}

- (HLCTimestamp)send { return [self now]; }

- (HLCTimestamp)receivePhysical:(uint64_t)msgPhys logical:(uint64_t)msgLog {
    uint64_t wall = wallMs();
    uint64_t oldPhys = _physicalMs;
    _physicalMs = std::max({oldPhys, msgPhys, wall});

    if (_physicalMs - wall > _maxDriftMs)
        throw std::runtime_error("HLC drift exceeds max");

    if (_physicalMs == oldPhys && oldPhys == msgPhys)
        _logical = std::max(_logical, msgLog) + 1;
    else if (_physicalMs == oldPhys)
        _logical += 1;
    else if (_physicalMs == msgPhys)
        _logical = msgLog + 1;
    else
        _logical = 0;

    return {_physicalMs, _logical, _nodeId};
}

@end

Request path / sequence

Trade-offs I'd say out loud

Lamport clock vs HLC

Lamport is simpler but drifts from wall time; HLC stays close to physical time.

HLC vs TrueTime

HLC is free (software only) but doesn't bound uncertainty; TrueTime needs GPS/atomic hardware.

Commit-wait latency vs consistency

Commit-wait adds ~7–14 ms per write but guarantees external consistency.

Event-time vs processing-time

Event-time gives correct semantics but requires watermarks and late-data handling.

Where it usually breaks

  • Using wall clock for last-writer-wins without accounting for NTP skew — silent data loss.
  • TTL based on wall time expiring early on a fast-clock node — premature cache eviction.
  • HLC not capping drift — logical clock advances into the far future via message chains.
  • Ignoring leap seconds — 1-second ambiguity window every few years.
  • Processing-time windows in stream processing — late data silently dropped.
