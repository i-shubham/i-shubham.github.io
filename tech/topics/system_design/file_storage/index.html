Design a file storage service

Object storage wraps blob durability; the product pain is resumable uploads, metadata search, and not serving malware.

60-minute agenda

How I'd open the discussion

I'd start by clarifying the expected file sizes. If most files are under 5 MB (like profile photos), a simple single-request upload works. But if we support files up to 5 GB (like video), we need chunked uploads with resumability — a user on a flaky connection should not restart a 2 GB upload from scratch. That design decision cascades through the entire architecture.

The second key question is the access pattern. If files are write-once-read-many (like a document sharing service), we can optimize for read throughput with CDN caching. If files are frequently updated (like a collaboration tool), we need versioning and conflict resolution.

I'd sketch four layers: an upload service that handles chunked uploads and reassembly, a blob store (S3 or a similar object store) for durable storage, a metadata database for file attributes and search, and an async virus-scanning pipeline that quarantines files until they pass.

Open questions worth asking

  • What is the maximum file size we need to support?
  • Do we need resumable uploads for large files?
  • Write-once-read-many, or frequent updates with versioning?
  • Do we need file sharing with access control (public/private/shared)?
  • Is full-text search on file contents in scope, or just metadata?
  • Do we need deduplication (same file uploaded by different users)?
  • What is the expected storage retention — indefinite or time-limited?
  • Do we need to scan files for malware before serving?
  • Is there a CDN requirement for download performance?
  • What client platforms — web, mobile, desktop?

Scope I'd lock first

  • In: chunked resumable upload, download with presigned URLs, metadata storage and search.
  • In: async virus scanning with quarantine, basic access control.
  • Out: real-time collaboration/editing, file versioning history.
  • Defer: content-based deduplication, preview/thumbnail generation, CDN integration.

  Response 202: { file_id, status: 'scanning' }

GET /api/v1/files/{file_id}
  Response 200: { file_id, filename, size, status, download_url, created_at, tags }

GET /api/v1/files?q=<search>&tags=<tag1,tag2>
  Response 200: { files[], total, next_cursor }

CREATE TABLE files (
  file_id      UUID PRIMARY KEY,
  owner_id     BIGINT NOT NULL,
  filename     VARCHAR(512) NOT NULL,
  size_bytes   BIGINT,
  content_type VARCHAR(128),
  s3_key       VARCHAR(1024),
  status       VARCHAR(16) DEFAULT 'uploading',  -- uploading|scanning|clean|quarantined
  checksum_sha256 CHAR(64),
  created_at   TIMESTAMP DEFAULT now()
);

-- Chunked upload tracking (Postgres or Redis)
CREATE TABLE upload_chunks (
  upload_id    UUID,
  chunk_no     INT,
  s3_part_key  VARCHAR(1024),
  checksum_md5 CHAR(32),
  received_at  TIMESTAMP,
  PRIMARY KEY (upload_id, chunk_no)
);

-- Tags for search (Elasticsearch mirrors this)
CREATE TABLE file_tags (
  file_id  UUID REFERENCES files(file_id),
  tag      VARCHAR(64),
  PRIMARY KEY (file_id, tag)
);

Approach / design notes

The upload flow has three phases: initiate, chunk upload, and complete. The client calls POST /uploads with file metadata. The upload service creates an upload record, calculates the number of chunks (file_size / chunk_size, typically 5 MB chunks), and returns presigned S3 URLs for each chunk. The client uploads chunks in parallel (up to 4 concurrent uploads for network efficiency). Each chunk goes directly to S3 via the presigned URL — the upload service never touches the file data, avoiding a bottleneck.

Resumability works because each chunk is tracked independently. If the upload fails after chunk 37 of 200, the client calls GET /uploads/{id}/status to see which chunks are received and resumes from chunk 38. The upload record has a TTL (e.g., 24 hours) — incomplete uploads are garbage-collected and their orphaned S3 parts are cleaned up by a background job.

When the client calls POST /uploads/{id}/complete, the upload service verifies all chunks are present, initiates an S3 multipart-upload completion (which assembles chunks into a single object server-side), and transitions the file status to 'scanning'. A message is published to an SQS queue for the virus scanner.

The virus scanner is a fleet of workers that download the file from S3, run ClamAV (or a commercial engine), and update the file status to 'clean' or 'quarantined'. Quarantined files are never served — download requests for quarantined files return 403. The scan is async to avoid blocking the upload response, but the file is not downloadable until the scan completes.

For downloads, the API generates a short-lived presigned S3 URL (valid for 15 minutes) and returns a 302 redirect. This offloads bandwidth to S3/CloudFront and avoids proxying file data through our servers. The presigned URL includes the file's content-disposition header to force the correct filename on download.

Deep dive (spend 15–25 minutes here)

Presigned URLs are the key architectural decision. By generating time-limited, authenticated URLs that point directly to S3, we avoid proxying file data through our application servers. A presigned PUT URL lets the client upload a chunk directly to S3 with a specific key and content-MD5 constraint. If the MD5 does not match, S3 rejects the upload — integrity checking is delegated to the storage layer. This means our upload service handles only metadata operations (a few KB per request), not multi-GB data transfers.

The virus scanning pipeline needs careful state management. A file goes through four states: uploading → scanning → clean (or quarantined). The state machine is enforced in the database with a CHECK constraint. Only clean files can be downloaded. The scan worker retries up to 3 times on transient failures (e.g., ClamAV process crash). If all retries fail, the file is marked 'scan_failed' and flagged for manual review. We monitor the scan queue depth and auto-scale workers when the backlog exceeds 1,000 files.

Content-based deduplication saves significant storage. After the file is assembled, we compute a SHA-256 hash of the entire file. If the hash matches an existing file, we create a new metadata record pointing to the same S3 object. Reference counting tracks how many metadata records point to each S3 object — the object is only deleted when the reference count reaches zero. This is a post-upload dedup strategy; inline dedup (checking before upload) would require the client to compute and send the hash first, adding a round trip.

For metadata search, I'd mirror the files table into Elasticsearch with fields for filename, content_type, tags, owner, and created_at. Searches like 'all PDFs tagged quarterly-report' become simple ES queries. The mirror is maintained via a change-data-capture (CDC) pipeline from Postgres to ES — so metadata writes go to Postgres (source of truth) and asynchronously propagate to ES. Search results may lag writes by a few seconds, which is acceptable.

Garbage collection is essential. Incomplete uploads leave orphaned S3 multipart parts that cost money. A daily cron job lists all S3 multipart uploads older than 24 hours and aborts them. Similarly, quarantined files that have been quarantined for more than 30 days are permanently deleted to reclaim storage.

Chunked upload service with S3 multipart and scan queue

import uuid
import hashlib
from datetime import datetime, timedelta

CHUNK_SIZE = 5 * 1024 * 1024  # 5 MB — S3 multipart minimum
UPLOAD_TTL = timedelta(hours=24)


class UploadService:
    def __init__(self, s3, db, scan_queue):
        self.s3 = s3              # boto3 S3 client
        self.db = db              # metadata database
        self.scan_queue = scan_queue  # antivirus scan queue

    def initiate(self, owner_id: int, filename: str, size: int) -> dict:
        """Start a chunked upload: create S3 multipart + presigned URLs."""
        upload_id = str(uuid.uuid4())
        num_chunks = (size + CHUNK_SIZE - 1) // CHUNK_SIZE
        s3_key = f"uploads/{upload_id}/{filename}"
        mpu = self.s3.create_multipart_upload(Bucket="files", Key=s3_key)
        chunk_urls = []
        for i in range(1, num_chunks + 1):
            url = self.s3.generate_presigned_url(
                "upload_part",
                Params={"Bucket": "files", "Key": s3_key,
                        "UploadId": mpu["UploadId"], "PartNumber": i},
                ExpiresIn=86400,
            )
            chunk_urls.append({"chunk_no": i, "url": url})
        self.db.insert_upload(upload_id, owner_id, filename, size,
                              s3_key, mpu["UploadId"], num_chunks)
        return {"upload_id": upload_id, "chunk_urls": chunk_urls}

    def complete(self, upload_id: str) -> dict:
        """Finalize upload: verify all chunks, complete S3 MPU, queue scan."""
        rec = self.db.get_upload(upload_id)
        received = self.db.get_received_chunks(upload_id)
        if len(received) != rec["num_chunks"]:
            missing = set(range(1, rec["num_chunks"] + 1)) - set(received)
            raise ValueError(f"Missing chunks: {missing}")
        parts = [{"PartNumber": c["chunk_no"], "ETag": c["etag"]}
                 for c in self.db.get_chunk_details(upload_id)]
        self.s3.complete_multipart_upload(
            Bucket="files", Key=rec["s3_key"],
            UploadId=rec["mpu_id"],
            MultipartUpload={"Parts": parts},
        )
        file_id = str(uuid.uuid4())
        # Mark as "scanning" until antivirus check completes
        self.db.insert_file(file_id, rec["owner_id"], rec["filename"],
                            rec["size"], rec["s3_key"], status="scanning")
        self.scan_queue.send({"file_id": file_id, "s3_key": rec["s3_key"]})
        return {"file_id": file_id, "status": "scanning"}
use std::collections::{HashMap, HashSet};
use uuid::Uuid;

const CHUNK_SIZE: u64 = 5 * 1024 * 1024; // 5 MB — S3 multipart minimum

struct UploadRecord {
    upload_id: String,
    owner_id: u64,
    filename: String,
    s3_key: String,
    mpu_id: String,
    num_chunks: u32,
}

/// Chunked upload service — manages S3 multipart lifecycle and virus scan queue.
struct UploadService {
    uploads: HashMap<String, UploadRecord>,
    received: HashMap<String, HashSet<u32>>, // upload_id → received chunk numbers
}

impl UploadService {
    fn new() -> Self {
        Self { uploads: HashMap::new(), received: HashMap::new() }
    }

    /// Start a chunked upload: compute chunk count, generate presigned URLs
    fn initiate(&mut self, owner_id: u64, filename: &str, size: u64)
        -> Result<(String, Vec<u32>), &'static str>
    {
        let upload_id = Uuid::new_v4().to_string();
        let num_chunks = ((size + CHUNK_SIZE - 1) / CHUNK_SIZE) as u32;
        let s3_key = format!("uploads/{}/{}", upload_id, filename);
        self.uploads.insert(upload_id.clone(), UploadRecord {
            upload_id: upload_id.clone(), owner_id,
            filename: filename.to_string(), s3_key,
            mpu_id: Uuid::new_v4().to_string(), num_chunks,
        });
        // In production: call S3 create_multipart_upload + generate_presigned_url
        let chunks: Vec<u32> = (1..=num_chunks).collect();
        Ok((upload_id, chunks))
    }

    /// Finalize: verify all chunks received, complete S3 MPU, queue scan
    fn complete(&self, upload_id: &str) -> Result<String, String> {
        let rec = self.uploads.get(upload_id)
            .ok_or("Upload not found")?;
        let received = self.received.get(upload_id)
            .map(|s| s.len() as u32).unwrap_or(0);
        if received != rec.num_chunks {
            return Err(format!("Missing chunks: got {}/{}", received, rec.num_chunks));
        }
        // In production: call S3 complete_multipart_upload
        let file_id = Uuid::new_v4().to_string();
        // Queue antivirus scan before marking file as available
        Ok(file_id)
    }
}
#import <Foundation/Foundation.h>
#include <unordered_map>
#include <unordered_set>
#include <string>

static const uint64_t kChunkSize = 5 * 1024 * 1024; // 5 MB

struct UploadRecord {
    std::string uploadID, filename, s3Key, mpuID;
    uint64_t ownerID;
    uint32_t numChunks;
};

// Manages chunked uploads with S3 multipart and antivirus scan queue
@interface UploadService : NSObject
- (NSDictionary *)initiateForOwner:(uint64_t)owner
                          filename:(NSString *)name
                              size:(uint64_t)size;
- (NSDictionary *)complete:(NSString *)uploadID error:(NSError **)error;
@end

@implementation UploadService {
    std::unordered_map<std::string, UploadRecord> _uploads;
    std::unordered_map<std::string, std::unordered_set<uint32_t>> _received;
}

- (NSDictionary *)initiateForOwner:(uint64_t)owner
                          filename:(NSString *)name
                              size:(uint64_t)size {
    NSString *uid = [NSUUID UUID].UUIDString;
    uint32_t numChunks = (uint32_t)((size + kChunkSize - 1) / kChunkSize);
    std::string key = uid.UTF8String;
    _uploads[key] = {key, name.UTF8String,
        "uploads/" + key + "/" + std::string(name.UTF8String),
        NSUUID.UUID.UUIDString.UTF8String, owner, numChunks};
    // Production: call S3 createMultipartUpload + generatePresignedURL
    NSMutableArray *chunks = [NSMutableArray new];
    for (uint32_t i = 1; i <= numChunks; i++)
        [chunks addObject:@(i)];
    return @{@"upload_id": uid, @"chunks": chunks};
}

- (NSDictionary *)complete:(NSString *)uploadID error:(NSError **)error {
    std::string key = uploadID.UTF8String;
    auto it = _uploads.find(key);
    if (it == _uploads.end()) {
        if (error) *error = [NSError errorWithDomain:@"Upload" code:404 userInfo:nil];
        return nil;
    }
    auto &rec = it->second;
    uint32_t got = (uint32_t)_received[key].size();
    if (got != rec.numChunks) {
        if (error) *error = [NSError errorWithDomain:@"Upload" code:400 userInfo:
            @{NSLocalizedDescriptionKey:
              [NSString stringWithFormat:@"Missing chunks: %u/%u", got, rec.numChunks]}];
        return nil;
    }
    // Production: complete S3 MPU, queue antivirus scan
    NSString *fileID = [NSUUID UUID].UUIDString;
    return @{@"file_id": fileID, @"status": @"scanning"};
}
@end

Request path / sequence

Trade-offs I'd say out loud

Presigned URL vs proxy

Presigned offloads bandwidth but exposes S3 structure; proxy gives control but bottlenecks throughput.

Sync vs async virus scan

Sync blocks upload response but guarantees safety; async is faster but serves a brief window of unscanned files.

Post-upload vs inline dedup

Post-upload is simpler but uploads redundant data; inline saves bandwidth but adds a round trip.

S3 vs self-managed blob store

S3 gives 11-nines durability out of the box; self-managed gives cost control but operational burden.

Where it usually breaks

  • Incomplete multipart uploads accumulate orphaned S3 parts — costs grow silently without GC.
  • Virus scanner falls behind during upload spikes — files stuck in 'scanning' state for hours.
  • Presigned URL expires before client finishes slow upload — chunk rejected, user must restart.
  • SHA-256 dedup collision (astronomically unlikely but not zero) — two different files share one object.
  • S3 eventual consistency on overwrite — rare read-after-write inconsistency for updated files.
  • Metadata DB out of sync with S3 — file record exists but S3 object was deleted externally.
