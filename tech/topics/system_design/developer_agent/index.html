Design a Codex-like coding agent

A developer agent is a tool loop plus a sandbox — unbounded repo context and runaway tool calls will bankrupt you before the model does.

60-minute agenda

How I'd open the discussion

I'd first lock where the agent runs. A local IDE plugin that reads the user's tree is a different product from a cloud agent that clones the repo into a VM and opens a PR. Cloud is the interesting system: you own compute, isolation, and billing. I'd also ask whether the agent may run tests, install packages, or hit the network — those answers size the sandbox.

The core is not "call an LLM." It is a durable session: user prompt in, a loop of model tokens → structured tool calls → sandbox results → packed context → next model step, until a stop condition. Streaming to the client is UX; persistence of the transcript and workspace snapshot is what makes reconnect and billing possible.

I'd sketch an orchestrator, a model gateway with token accounting, a repo index for retrieval, and a pool of sandboxed workers — then deep-dive context packing and tool policy, which is where these systems actually fail.

Open questions worth asking

  • Local-only (user machine) or cloud workspace that can open PRs?
  • Max repo size and whether monorepos are in scope?
  • May the agent write files, run tests, and use the network?
  • Human-in-the-loop: auto-apply edits vs approval for every patch?
  • Latency target for first token vs time-to-green-tests?
  • Which models — one frontier model or a router (cheap + strong)?
  • Multi-file refactors spanning hours — resume after disconnect?
  • Enterprise: SSO, VPC, no training on customer code?
  • Languages / runtimes we must support in the sandbox?
  • Do we need evals / regression suites for agent quality?

Scope I'd lock first

  • In: cloud coding agent, clone-or-sync workspace, read/search/edit/test tools, streaming UI.
  • In: sandbox isolation, step/time/token budgets, session resume, usage metering.
  • Out: training custom models, IDE pixel-perfect plugin, org-wide multi-agent swarms.
  • Defer: autonomous overnight jobs across hundreds of repos unless interviewer pushes.

Functional requirements

Task session

User starts a task against a repo/ref; agent streams thoughts, diffs, and command output.

Tools

Search, read file, apply patch, run tests/linters inside a sandbox with policy.

Context

Retrieve relevant files/symbols; pack a window that fits the model without dumping the repo.

Resume

Reconnect to an in-flight session; persist workspace snapshot + transcript.

Handoff

Produce a branch/PR or a local patch the user can apply.

Non-functional / rough numbers

First token

p50 < 1s after prompt hits the orchestrator (warm model connection).

Task duration

Seconds to ~20 min typical; hard cap per session (e.g. 45 min wall, 200 tool steps).

Isolation

Untrusted code must not escape the sandbox or steal other tenants' secrets.

Cost

Token + sandbox-minute budgets per user/org; kill runaway loops.

Capacity estimate (do this on the board)

Sessions

1M DAU × 3 tasks/day × 8 min avg = ~167K concurrent sessions at peak (assume 8h spread, 3× peak).

Model QPS

Each session ~1 model call / 8s → ~20K inflight generations; GPU fleet sized for that plus queue.

Context

Avg 32K tokens in / 2K out per step × 20 steps → ~640K in-tokens/task; retrieval must beat stuffing the repo.

Sandbox

167K sessions cannot each own a fat VM — pool warm snapshots, recycle after idle.

Index

10M repos × incremental embeddings/AST; shard by repo_id, rebuild on push.

Storage

Transcripts + diffs + workspace snapshots (copy-on-write layers) for 7–30 days.

Approach / design notes

The orchestrator owns session state. On start it allocates a sandbox from a warm pool (pre-baked images per language: Python/Node/JVM/etc.), checks out the requested commit, and attaches a network policy. A model gateway streams completions with tool-call JSON. The orchestrator validates each call against a allowlist (path prefixes, command binary allowlist, env without secrets unless injected as scoped tokens), executes in the sandbox, truncates output, appends to the transcript, and packs the next prompt.

Repo understanding is retrieval, not "send the whole tree." A background indexer builds symbol + embedding indexes per commit. At task start the agent searches (ripgrep-in-sandbox plus vector/symbol search) and pins a working set. Context packing drops stale tool output, summarizes old steps, and always keeps the user prompt + latest diffs.

Streaming is a fan-out from orchestrator to the client; the source of truth is the step log so a refresh can replay. Long jobs checkpoint the workspace as a copy-on-write snapshot so a crashed worker can resume. Billing meters tokens at the gateway and sandbox-minutes at the worker pool; both have hard kill switches.

Deep dive (spend 15–25 minutes here)

Tool policy is the difference between a demo and a product. File tools are jailed to the workspace. Shell is not a raw bash pipe — it is an allowlisted runner (pytest, cargo test, linters) with CPU/memory/time cgroups. Network is default-deny except package registries and the user's git remote. Destructive git force-push and credential files are blocked or require explicit approval events.

Context overflow is the silent quality killer. A naive loop concatenates every tool result until the model degrades or the bill explodes. I'd keep a sliding window: always include system policy + user goal + current file map; summarize completed steps; store full logs in object storage for debug, not in the prompt. Retrieval should be re-run when the agent changes directories or the task drifts.

Sandbox pooling: cold VMs are too slow for first-token UX. Keep a queue of snapshots with common toolchains. After a task, either recycle (if the tree is dirty, discard the layer) or snapshot for resume. Multi-tenant isolation: separate kernel/gVisor/Firecracker-style VMs, not shared Docker-with-hope. Secrets: never bake GitHub tokens into the prompt; inject short-lived tokens into the sandbox env and audit their use.

Model routing: cheap model for search/planning, stronger model for patches. Queue fairness so one org cannot starve GPUs. Cache prompt prefixes (policy + repo map) on the inference side when the vendor supports it.

Tool loop with policy and context packing

from dataclasses import dataclass, field
from typing import Callable, Dict, List, Optional

MAX_STEPS = 200
MAX_TOOL_CHARS = 8_000
ALLOWED_TOOLS = {"read", "search", "edit", "test"}


@dataclass
class Step:
    kind: str
    content: str


@dataclass
class Session:
    goal: str
    steps: List[Step] = field(default_factory=list)
    tokens_in: int = 0


def pack_context(session: Session, budget_chars: int = 80_000) -> str:
    """Keep the goal and recent steps; drop old tool dumps first."""
    parts = [f"GOAL:\n{session.goal}"]
    used = len(parts[0])
    kept: List[str] = []
    for step in reversed(session.steps):
        chunk = f"{step.kind.upper()}:\n{step.content}"
        if used + len(chunk) > budget_chars:
            break
        kept.append(chunk)
        used += len(chunk)
    parts.extend(reversed(kept))
    return "\n\n".join(parts)


def authorize(name: str, args: Dict) -> Optional[str]:
    if name not in ALLOWED_TOOLS:
        return f"tool {name} is not allowed"
    path = str(args.get("path", ""))
    if path.startswith("/") or ".." in path.split("/"):
        return "path escapes the workspace"
    return None


class AgentLoop:
    def __init__(self, model, sandbox: Callable[[str, Dict], str]):
        self.model = model
        self.sandbox = sandbox

    def run(self, session: Session) -> Session:
        for _ in range(MAX_STEPS):
            prompt = pack_context(session)
            event = self.model.complete(prompt)  # {type, name?, args?, text?}
            if event["type"] == "stop":
                session.steps.append(Step("model", event.get("text", "")))
                return session
            if event["type"] != "tool":
                continue
            err = authorize(event["name"], event.get("args") or {})
            if err:
                session.steps.append(Step("tool", f"denied: {err}"))
                continue
            raw = self.sandbox(event["name"], event["args"])
            session.steps.append(Step("tool", raw[:MAX_TOOL_CHARS]))
        session.steps.append(Step("model", "stopped: step budget"))
        return session
use std::collections::HashMap;

const MAX_STEPS: usize = 200;
const MAX_TOOL_CHARS: usize = 8_000;
const CTX_BUDGET: usize = 80_000;

struct Step {
    kind: &'static str,
    content: String,
}

struct Session {
    goal: String,
    steps: Vec<Step>,
}

fn pack_context(session: &Session) -> String {
    let mut parts = vec![format!("GOAL:\n{}", session.goal)];
    let mut used = parts[0].len();
    let mut kept = Vec::new();
    for step in session.steps.iter().rev() {
        let chunk = format!("{}:\n{}", step.kind.to_uppercase(), step.content);
        if used + chunk.len() > CTX_BUDGET {
            break;
        }
        used += chunk.len();
        kept.push(chunk);
    }
    kept.reverse();
    parts.extend(kept);
    parts.join("\n\n")
}

fn authorize(name: &str, args: &HashMap<String, String>) -> Option<String> {
    match name {
        "read" | "search" | "edit" | "test" => {}
        other => return Some(format!("tool {other} is not allowed")),
    }
    if let Some(path) = args.get("path") {
        if path.starts_with('/') || path.split('/').any(|p| p == "..") {
            return Some("path escapes the workspace".into());
        }
    }
    None
}

struct AgentLoop<M, S>
where
    M: Fn(&str) -> HashMap<String, String>,
    S: Fn(&str, &HashMap<String, String>) -> String,
{
    model: M,
    sandbox: S,
}

impl<M, S> AgentLoop<M, S>
where
    M: Fn(&str) -> HashMap<String, String>,
    S: Fn(&str, &HashMap<String, String>) -> String,
{
    fn run(&self, session: &mut Session) {
        for _ in 0..MAX_STEPS {
            let event = (self.model)(&pack_context(session));
            if event.get("type").map(|s| s.as_str()) == Some("stop") {
                session.steps.push(Step {
                    kind: "model",
                    content: event.get("text").cloned().unwrap_or_default(),
                });
                return;
            }
            let name = event.get("name").map(|s| s.as_str()).unwrap_or("");
            let args = event.clone();
            if let Some(err) = authorize(name, &args) {
                session.steps.push(Step { kind: "tool", content: format!("denied: {err}") });
                continue;
            }
            let mut raw = (self.sandbox)(name, &args);
            raw.truncate(MAX_TOOL_CHARS);
            session.steps.push(Step { kind: "tool", content: raw });
        }
        session.steps.push(Step { kind: "model", content: "stopped: step budget".into() });
    }
}

Request path / sequence

Trade-offs I'd say out loud

Local vs cloud sandbox

Local is faster and cheaper isolation-wise; cloud is the only way to standardize runtimes and bill usage.

Auto-apply vs approve

Auto-apply feels like Codex; approval is safer for prod repos and slower for flow.

One fat model vs router

Router saves cost on search steps; adds failure modes when the cheap model plans badly.

Full clone vs sparse checkout

Sparse is faster for monorepos; agents then miss files they never fetched.

Where it usually breaks

  • Unbounded tool loop — agent retries failing tests until the token budget is a rounding error.
  • Prompt stuffed with the whole monorepo — latency and quality collapse together.
  • Shared-kernel containers — one tenant reads another's checkout or cloud metadata.
  • Secrets in the prompt or in world-readable sandbox files — leaked in logs and eval traces.
  • Index lagging HEAD — agent edits based on stale symbols while tests run on new code.
  • GPU queue unfairness — a few long sessions starve interactive users.

Follow-ups if time remains

  • How would you run overnight repo-wide migrations with per-PR batching?
  • Multi-agent: planner vs implementer vs reviewer without thrashing the tree.
  • Enterprise VPC: model stays in-region, no code used for training.
  • Eval harness: frozen tasks with hidden tests so you do not overfit demos.
  • IDE plugin that shares the same orchestrator protocol as the cloud agent.

What "good enough" looks like in 60 minutes

Draw a durable session loop (model ↔ policy ↔ sandbox), explain retrieval + context packing instead of dumping the repo, and size GPU plus warm sandbox pools. Call out step/token kill switches and path/command allowlists. Fine-tuning and multi-agent orgs can stay as follow-ups.
