Longest substring without repeating characters

The sliding window poster child — easy to sketch, easy to get the left pointer wrong on repeats.

60-minute agenda

How I'd open the discussion

I'd say this is the canonical sliding window problem. The brute-force approach checks all O(n²) substrings and validates each with a set — that's O(n³). We can drop it to O(n) by maintaining a window [left, right] and a map of character → last-seen index.

When we see a repeat of char c, we don't just move left by one. We jump left to max(left, last_seen[c] + 1). The max is critical — without it, left can go backwards when a character repeats from before the current window. I've seen senior engineers miss this in interviews. I'd draw the example 'abba' to show why.

Open questions worth asking

  • ASCII only, or full Unicode / emoji?

  • Is the input always a string, or can it be a generic sequence?
  • Case-sensitive? 'A' != 'a'?
  • Any constraint on string length (for overflow concerns)?
  • Online / streaming variant where we report max so far?

Scope I'd lock first

  • In: optimal O(n) sliding window returning length.
  • Out: returning all such substrings or k-distinct variant unless follow-up.

Functional requirements

  • Given string s, return length of longest substring with all unique characters.
  • Empty string returns 0.
  • String with all unique chars returns len(s).

Approach / design notes

Maintain a window [left, right]. Keep a dict last_seen mapping character → its most recent index. For each right, if s[right] was seen at index j and j >= left, move left to j + 1. Update last_seen[s[right]] = right. Track max_len = max(max_len, right - left + 1).

The key insight is the left pointer only moves forward. Each character is visited at most twice (once by right, possibly once by left jumping past it), giving amortized O(n).

Alternative: use a set and explicitly remove characters from the left until the duplicate is gone. This is still O(n) amortized but does more work per step — the last_seen map approach is cleaner because left jumps directly.

Deep dive (spend 15–25 minutes here)

Walk through s = 'abba'.

right=0 (a): last_seen={}, a not seen. last_seen={a:0}. max_len=1, window='a'. right=1 (b): b not seen. last_seen={a:0, b:1}. max_len=2, window='ab'. right=2 (b): b last seen at 1, 1 >= left(0), so left = 1+1 = 2. last_seen={a:0, b:2}. max_len stays 2, window='b'. right=3 (a): a last seen at 0, but 0 < left(2). So left stays at 2. This is where max(left, last_seen[c]+1) saves us. last_seen={a:3, b:2}. max_len stays 2, window='ba'.

Without the max check, left would jump back to 0+1=1, giving window 'bba' which contains a repeat. Bug.

Now trace s = 'pwwkew': right=0 (p): window='p', len=1. right=1 (w): window='pw', len=2. right=2 (w): w at 1 >= left(0), left=2. window='w', len=1. right=3 (k): window='wk', len=2. right=4 (e): window='wke', len=3. max_len=3. right=5 (w): w at 2, but 2 >= left(2), so left=3. window='kew', len=3. Answer: 3 ('wke' or 'kew').

Sliding window with last-seen map (dict + ASCII array variants)

def length_of_longest_substring(s: str) -> int:
    """Sliding window with a dict tracking each character's last-seen index.
    When a repeat is found inside the window, jump left past it."""
    last_seen = {}
    left = 0
    max_len = 0
    for right, ch in enumerate(s):
        if ch in last_seen and last_seen[ch] >= left:
            # Shrink window: move left pointer past the previous occurrence
            left = last_seen[ch] + 1
        last_seen[ch] = right
        max_len = max(max_len, right - left + 1)
    return max_len


def length_of_longest_substring_array(s: str) -> int:
    """Optimised for ASCII input: fixed-size int array instead of hash map.
    Avoids hashing overhead — useful in tight interview follow-ups."""
    last_seen = [-1] * 128
    left = 0
    max_len = 0
    for right, ch in enumerate(s):
        idx = ord(ch)
        if last_seen[idx] >= left:
            left = last_seen[idx] + 1
        last_seen[idx] = right
        max_len = max(max_len, right - left + 1)
    return max_len
use std::collections::HashMap;

/// Sliding window with HashMap tracking last-seen index of each character.
fn length_of_longest_substring(s: &str) -> usize {
    let mut last_seen: HashMap<char, usize> = HashMap::new();
    let mut left = 0usize;
    let mut max_len = 0usize;
    for (right, ch) in s.chars().enumerate() {
        if let Some(&prev) = last_seen.get(&ch) {
            if prev >= left {
                // Shrink window past the previous occurrence
                left = prev + 1;
            }
        }
        last_seen.insert(ch, right);
        max_len = max_len.max(right - left + 1);
    }
    max_len
}

/// ASCII-optimised variant: fixed [i32; 128] array avoids hashing overhead.
fn length_of_longest_substring_array(s: &[u8]) -> usize {
    let mut last_seen = [-1i64; 128];
    let mut left: i64 = 0;
    let mut max_len: usize = 0;
    for (right, &b) in s.iter().enumerate() {
        let idx = b as usize;
        if last_seen[idx] >= left {
            left = last_seen[idx] + 1;
        }
        last_seen[idx] = right as i64;
        max_len = max_len.max((right as i64 - left + 1) as usize);
    }
    max_len
}
#import <Foundation/Foundation.h>
#include <string>
#include <unordered_map>
#include <algorithm>

// Sliding window with unordered_map tracking last-seen index
static int lengthOfLongestSubstring(const std::string &s) {
    std::unordered_map<char, int> lastSeen;
    int left = 0, maxLen = 0;
    for (int right = 0; right < (int)s.size(); right++) {
        char ch = s[right];
        auto it = lastSeen.find(ch);
        if (it != lastSeen.end() && it->second >= left) {
            // Shrink window past the previous occurrence
            left = it->second + 1;
        }
        lastSeen[ch] = right;
        maxLen = std::max(maxLen, right - left + 1);
    }
    return maxLen;
}

// ASCII-optimised: fixed int array avoids hashing overhead
static int lengthOfLongestSubstringArray(const std::string &s) {
    int lastSeen[128];
    std::fill(lastSeen, lastSeen + 128, -1);
    int left = 0, maxLen = 0;
    for (int right = 0; right < (int)s.size(); right++) {
        int idx = (unsigned char)s[right];
        if (lastSeen[idx] >= left)
            left = lastSeen[idx] + 1;
        lastSeen[idx] = right;
        maxLen = std::max(maxLen, right - left + 1);
    }
    return maxLen;
}

// NSString convenience wrapper using the C++ implementation above
static NSInteger longestUniqueSubstring(NSString *str) {
    return lengthOfLongestSubstring(str.UTF8String);
}

Request path / sequence

Trade-offs I'd say out loud

Map vs set

Map gives O(1) left-jump; set requires O(k) removals to slide left.

Array vs dict

If ASCII-only, int[128] is faster than a hash map — cache-friendly.

Length vs substring

If you also need the substring, track start index of best window.

Where it usually breaks

  • Left pointer going backwards without the max() guard — 'abba' is the classic breaker.
  • Off-by-one: right - left + 1 vs right - left.
  • Not handling empty string (should return 0, not crash).
  • Forgetting to update last_seen after moving left.
  • Assuming ASCII when input is Unicode — dict handles both, array doesn't.

Follow-ups if time remains

  • Longest substring with at most k distinct characters — generalize with a freq map and count.
  • Minimum window substring — shrink-from-left variant with a 'formed' counter.
  • Longest repeating character replacement — window + max-frequency trick.
  • Sliding window template — right expands, left contracts, invariant maintained.

What "good enough" looks like in 60 minutes

Clean O(n) code with the last_seen map, correct max() guard on left, traced through 'abba' to show the subtle bug, and discussed the set-based alternative. Mentioning the ASCII array optimization and connecting to the sliding window template earns extra credit.
