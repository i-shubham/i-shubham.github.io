1. Problem statement & explanation

There are numCourses courses labelled 0 … numCourses-1. You are given a list prerequisites where prerequisites[i] = [a, b] means you must take course b before course a. Return true if it is possible to finish all courses (Course Schedule I), or return a valid order in which to take them (Course Schedule II).

Translate it immediately: this is a directed graph with an edge b → a for every pair [a, b]. “Can I finish all courses?” is precisely “is this graph a DAG?”, and “in what order?” is precisely “give me a topological ordering.” A valid ordering exists if and only if the graph has no directed cycle — a cycle means a set of courses each waiting on another, so none of them can ever be started.

Both parts are solved by the same algorithm. That is the observation worth making early: you do not need one algorithm for the boolean and another for the order. A topological sort produces the order and, by failing to produce a full one, also answers the boolean.

1.1 Input / output

Signature

contract

Worked examples

Example 1 — simple chain 
Input:  numCourses = 2, prerequisites = [[1,0]]
        # "to take 1, first take 0"  =>  edge 0 -> 1
Output: canFinish = true,  findOrder = [0,1]
Example 2 — the cycle 
Input:  numCourses = 2, prerequisites = [[1,0],[0,1]]
        # 0 -> 1 and 1 -> 0
Output: canFinish = false, findOrder = []
Why:    each course waits on the other; neither can ever start.
Example 3 — diamond, multiple valid answers 
Input:  numCourses = 4, prerequisites = [[1,0],[2,0],[3,1],[3,2]]
        # 0 -> 1, 0 -> 2, 1 -> 3, 2 -> 3
Output: canFinish = true
        findOrder = [0,1,2,3]  OR  [0,2,1,3]   -- both correct
Why:    the answer is not unique. Confirm "any valid order" is acceptable.
Example 4 — the ones people forget 
numCourses = 1, prerequisites = []       -> true,  [0]
numCourses = 3, prerequisites = []       -> true,  [0,1,2]   (no edges at all)
numCourses = 1, prerequisites = [[0,0]]  -> false, []        (SELF-LOOP)
numCourses = 5, prerequisites = [[1,0],[4,3]] -> true, [0,3,1,4]
                                                # two disconnected components

Constraints to state back

  • 1 ≤ numCourses ≤ 2000, 0 ≤ prerequisites.length ≤ 5000. So V ≤ 2 × 10³ and E ≤ 5 × 10³ — tiny; O(V+E) is instant and even O(V²) passes.
  • prerequisites[i].length == 2, 0 ≤ a, b < numCourses, all pairs distinct. Distinct pairs does not forbid a == b, so a self-loop is legal input and must return false.
  • Output for part I is a boolean. For part II, any valid topological order; [] signals impossibility — note that [] is also the correct answer when numCourses = 0, so the caller cannot distinguish them from the return value alone.
  • Courses with no prerequisites and no dependents still belong in the output. Disconnected components are normal, not an error.

2. Open questions & clarifications

  • Which way does the edge point? Does [a, b] mean “a before b” or “b before a”? Read the example back to the interviewer to confirm. Reversing this produces a reversed answer that still looks plausible, which is why it is the most expensive mistake in this problem.
  • Boolean, or the actual ordering? Same algorithm, different return. Ask so you write the right signature once.
  • Can a course be its own prerequisite? [[0,0]] is a self-loop and must be false. Some hand-rolled cycle checks miss it.
  • Can the same pair appear twice? Duplicate edges inflate in-degree by 2 and are decremented twice, so Kahn's handles them correctly — but only if you do not deduplicate on one side and not the other.
  • Are course IDs a dense 0 … n-1 range, or arbitrary strings? Dense integers let me use arrays; strings need a map from ID to index, which adds a hashing term.
  • Multiple valid orderings — is any one acceptable? If they want the lexicographically smallest, swap the queue for a min-heap: O((V+E) log V).
  • Disconnected components allowed? Yes here. Seeding the queue with all zero-in-degree nodes is what covers them; a single-source BFS would silently drop entire components.
  • How large can V and E get? At the stated 2000/5000 anything works. If the interviewer says a million nodes, recursive DFS is out (stack depth) and iterative Kahn's is the only safe choice.
  • Do you want to know which courses form the cycle, or only that one exists? Reporting the cycle is a real follow-up and favours DFS, which has the path on the stack.
  • Is the input trusted? Should out-of-range course IDs be validated or assumed well-formed?

2.1 Suggestions to the candidate

  • Do not jump to “topological sort” and start typing. First say the equivalence in words: “a valid schedule exists exactly when the prerequisite graph is acyclic.” That sentence is what the question is testing. The algorithm is the easy part.
  • Draw the graph for example 3 before you write code. Four nodes and four arrows on the whiteboard. It fixes the edge direction in your head and gives you a trace target for later.
  • Do not open with the optimal solution. Describe the repeated-scan baseline in three sentences and give its complexity. It costs you 90 seconds and demonstrates that O(V+E) was derived, not remembered.
  • State the termination condition before you code it. “If the topological order contains fewer than numCourses entries, the leftovers are trapped in a cycle.” Candidates who add this check as an afterthought usually forget it.
  • Prefer Kahn's under pressure. It is iterative, has one obvious invariant (in-degree zero means every prerequisite is satisfied), and gives you the ordering for free. Recursive DFS with three colours is elegant but has more state to keep straight while someone watches.
  • If you do use DFS, do not use a plain visited boolean. You need three states. Two states cannot distinguish “on the current path” (a cycle) from “finished and safe” (a shared dependency). Say this out loud — it is a known discriminator.
  • Trace a cyclic input yourself. On [[1,0],[0,1]] both in-degrees are 1, the queue starts empty, the loop never runs, the order has length 0. Showing that the failure mode is graceful is worth more than another passing example.
  • Name the real-world analogue once. Build systems, package managers, Airflow DAGs, migration ordering. One sentence, then back to code.

3. Brute-force approach

Simulate a student. Repeatedly scan all courses looking for one that is not yet taken and whose prerequisites are all taken; take it. Repeat numCourses times. If a round finds nothing takeable, the remaining courses are deadlocked.

  1. Build prereqs[c] = the list of courses that must precede c.
  2. Keep a boolean array taken.
  3. Repeat numCourses times: scan c = 0 … V-1 for the first untaken course all of whose prerequisites are taken; mark it taken and append it to the order.
  4. If a full scan finds no such course, return failure — every remaining course is waiting on another remaining course, which is a cycle by definition.
There is a worse brute force — name it and reject it

You could enumerate all V! permutations and test each against the constraints. At V = 2000 that is not a number worth writing down. Mentioning it once establishes the search space; do not dwell on it.

3.1 Code — Python, Rust, Java, C++

from typing import List


def find_order_brute(num_courses: int,
                     prerequisites: List[List[int]]) -> List[int]:
    """Repeatedly pick any course whose prerequisites are all satisfied.

    prerequisites[i] = [course, prereq] means prereq must come first.
    Returns [] when no valid order exists.
    """
    prereqs: List[List[int]] = [[] for _ in range(num_courses)]
    for course, prereq in prerequisites:
        prereqs[course].append(prereq)

    taken = [False] * num_courses
    order: List[int] = []

    for _ in range(num_courses):
        picked = -1
        for c in range(num_courses):       # full rescan every single round
            if not taken[c] and all(taken[p] for p in prereqs[c]):
                picked = c
                break
        if picked == -1:                   # nothing takeable => deadlock
            return []
        taken[picked] = True
        order.append(picked)

    return order


def can_finish_brute(num_courses: int, prerequisites: List[List[int]]) -> bool:
    return len(find_order_brute(num_courses, prerequisites)) == num_courses
/// Repeatedly pick any course whose prerequisites are all satisfied.
///
/// `prerequisites` holds (course, prereq) pairs: prereq must come first.
/// Returns `None` when no valid order exists.
pub fn find_order_brute(
    num_courses: usize,
    prerequisites: &[(usize, usize)],
) -> Option<Vec<usize>> {
    let mut prereqs: Vec<Vec<usize>> = vec![Vec::new(); num_courses];
    for &(course, prereq) in prerequisites {
        prereqs[course].push(prereq);
    }

    let mut taken = vec![false; num_courses];
    let mut order = Vec::with_capacity(num_courses);

    for _ in 0..num_courses {
        // Full rescan every single round -- this is the quadratic term.
        let picked = (0..num_courses)
            .find(|&c| !taken[c] && prereqs[c].iter().all(|&p| taken[p]));

        match picked {
            Some(c) => {
                taken[c] = true;
                order.push(c);
            }
            None => return None,           // nothing takeable => deadlock
        }
    }
    Some(order)
}
import java.util.ArrayList;
import java.util.List;

class Solution {

    /**
     * Repeatedly pick any course whose prerequisites are all satisfied.
     * prerequisites[i] = {course, prereq} means prereq must come first.
     * Returns an empty array when no valid order exists.
     */
    public int[] findOrderBrute(int numCourses, int[][] prerequisites) {
        List<List<Integer>> prereqs = new ArrayList<>(numCourses);
        for (int i = 0; i < numCourses; i++) {
            prereqs.add(new ArrayList<>());
        }
        for (int[] pair : prerequisites) {
            prereqs.get(pair[0]).add(pair[1]);
        }

        boolean[] taken = new boolean[numCourses];
        int[] order = new int[numCourses];

        for (int filled = 0; filled < numCourses; filled++) {
            int picked = -1;
            for (int c = 0; c < numCourses && picked < 0; c++) {
                if (taken[c]) continue;
                boolean ready = true;
                for (int p : prereqs.get(c)) {   // full rescan every round
                    if (!taken[p]) { ready = false; break; }
                }
                if (ready) picked = c;
            }
            if (picked < 0) return new int[0];   // deadlock => cycle
            taken[picked] = true;
            order[filled] = picked;
        }
        return order;
    }
}

3.2 Complexity

Time O(V² + V·E)

V rounds, each scanning V courses and re-checking their prerequisite lists (E edges in total). At V = 2000, E = 5000 that is ~10⁷ operations — still fast, but the shape is wrong.

Space O(V + E)

The reversed adjacency (prereqs per course) plus the taken array and the output order.

Why this is not the final answer

Taking course c can only ever make progress for the courses that depend on c. Rescanning all V courses re-derives “still blocked” for everything else. If instead each course carries a counter of unmet prerequisites, taking c means decrementing that counter only along c's outgoing edges — total work O(E) across the whole run instead of O(V·E).

4. Optimised approach

Key insight (Kahn's algorithm): store indeg[c] = the number of prerequisites of c that are not yet taken. A course is takeable exactly when indeg[c] == 0. Keep all takeable courses in a queue. Taking a course decrements the in-degree of each of its direct dependents, and any dependent that reaches zero joins the queue. Each node is enqueued once and each edge is examined once.

  1. Build the forward adjacency list: for every pair [a, b], add edge b → a and increment indeg[a].
  2. Seed the queue with every node whose indeg is 0 — not just node 0. This is what handles disconnected components.
  3. Pop node, append it to order. For each neighbour, decrement its in-degree; if it hits 0, enqueue it.
  4. When the queue drains: if len(order) == numCourses the graph is a DAG and order is a valid schedule. Otherwise the missing courses are exactly the ones on or downstream of a cycle.
The invariant to say out loud

A node is enqueued only when every one of its prerequisites has already been appended to order. So the output is a valid topological order by construction. And since every node with in-degree 0 is enqueued, any node never enqueued must have kept a positive in-degree forever — i.e. it sits on or behind a cycle.

Now trace the cyclic input

prerequisites = [[1,0],[0,1]] gives edges 0→1 and 1→0, so indeg = [1, 1]. No node has in-degree 0, the queue starts empty, the while loop never executes, order is [], and 0 ≠ 2 reports the cycle. Nothing special-cased; the counting argument handles it.

4.1 Code — Python, Rust, Java, C++

from collections import deque
from typing import List


def find_order(num_courses: int, prerequisites: List[List[int]]) -> List[int]:
    """Kahn's algorithm: BFS topological sort.

    prerequisites[i] = [course, prereq] => directed edge prereq -> course.
    Returns a valid order, or [] if the graph has a cycle.
    """
    adj: List[List[int]] = [[] for _ in range(num_courses)]
    indeg = [0] * num_courses
    for course, prereq in prerequisites:
        adj[prereq].append(course)         # DIRECTION: prereq unlocks course
        indeg[course] += 1                 # course has one more unmet prereq

    # Seed with EVERY zero-indegree node -- this covers disconnected parts.
    queue = deque(c for c in range(num_courses) if indeg[c] == 0)

    order: List[int] = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in adj[node]:
            indeg[nxt] -= 1                # one prerequisite now satisfied
            if indeg[nxt] == 0:
                queue.append(nxt)

    # Short order => some nodes never reached in-degree 0 => cycle.
    return order if len(order) == num_courses else []


def can_finish(num_courses: int, prerequisites: List[List[int]]) -> bool:
    return len(find_order(num_courses, prerequisites)) == num_courses
use std::collections::VecDeque;

/// Kahn's algorithm: BFS topological sort.
///
/// `prerequisites` holds (course, prereq) pairs => edge prereq -> course.
/// Returns `Some(order)` for a DAG, `None` when a cycle exists.
pub fn find_order(
    num_courses: usize,
    prerequisites: &[(usize, usize)],
) -> Option<Vec<usize>> {
    let mut adj: Vec<Vec<usize>> = vec![Vec::new(); num_courses];
    let mut indeg = vec![0usize; num_courses];
    for &(course, prereq) in prerequisites {
        adj[prereq].push(course);          // DIRECTION: prereq unlocks course
        indeg[course] += 1;
    }

    // Seed with EVERY zero-indegree node -- this covers disconnected parts.
    let mut queue: VecDeque<usize> =
        (0..num_courses).filter(|&c| indeg[c] == 0).collect();

    let mut order = Vec::with_capacity(num_courses);
    while let Some(node) = queue.pop_front() {
        order.push(node);
        for i in 0..adj[node].len() {
            let nxt = adj[node][i];
            indeg[nxt] -= 1;               // one prerequisite now satisfied
            if indeg[nxt] == 0 {
                queue.push_back(nxt);
            }
        }
    }

    // Short order => some nodes never reached in-degree 0 => cycle.
    if order.len() == num_courses { Some(order) } else { None }
}

pub fn can_finish(num_courses: usize, prerequisites: &[(usize, usize)]) -> bool {
    find_order(num_courses, prerequisites).is_some()
}
import java.util.ArrayDeque;
import java.util.ArrayList;
import java.util.Deque;
import java.util.List;

class Solution {

    /**
     * Kahn's algorithm: BFS topological sort.
     * prerequisites[i] = {course, prereq} => edge prereq -> course.
     * Returns a valid order, or an empty array if a cycle exists.
     */
    public int[] findOrder(int numCourses, int[][] prerequisites) {
        List<List<Integer>> adj = new ArrayList<>(numCourses);
        for (int i = 0; i < numCourses; i++) {
            adj.add(new ArrayList<>());
        }
        int[] indeg = new int[numCourses];
        for (int[] pair : prerequisites) {
            adj.get(pair[1]).add(pair[0]);   // DIRECTION: prereq -> course
            indeg[pair[0]]++;
        }

        // Seed with EVERY zero-indegree node -- covers disconnected parts.
        Deque<Integer> queue = new ArrayDeque<>();
        for (int c = 0; c < numCourses; c++) {
            if (indeg[c] == 0) queue.add(c);
        }

        int[] order = new int[numCourses];
        int filled = 0;
        while (!queue.isEmpty()) {
            int node = queue.poll();
            order[filled++] = node;
            for (int nxt : adj.get(node)) {
                if (--indeg[nxt] == 0) {     // last prerequisite satisfied
                    queue.add(nxt);
                }
            }
        }

        // Short order => some nodes never reached in-degree 0 => cycle.
        return filled == numCourses ? order : new int[0];
    }

    public boolean canFinish(int numCourses, int[][] prerequisites) {
        return findOrder(numCourses, prerequisites).length == numCourses;
    }
}

#include <vector>

// Kahn's algorithm: BFS topological sort.
// prerequisites[i] = {course, prereq} => edge prereq -> course.
// Returns a valid order, or an empty vector if a cycle exists.
std::vector<int> findOrder(
        int numCourses,
        const std::vector<std::vector<int>>& prerequisites) {
    std::vector<std::vector<int>> adj(numCourses);
    std::vector<int> indeg(numCourses, 0);
    for (const auto& pair : prerequisites) {
        adj[pair[1]].push_back(pair[0]);     // DIRECTION: prereq -> course
        ++indeg[pair[0]];
    }

    // Seed with EVERY zero-indegree node -- covers disconnected parts.
    std::queue<int> q;
    for (int c = 0; c < numCourses; ++c) {
        if (indeg[c] == 0) q.push(c);
    }

    std::vector<int> order;
    order.reserve(numCourses);
    while (!q.empty()) {
        const int node = q.front();
        q.pop();
        order.push_back(node);
        for (int nxt : adj[node]) {
            if (--indeg[nxt] == 0) {         // last prerequisite satisfied
                q.push(nxt);
            }
        }
    }

    // Short order => some nodes never reached in-degree 0 => cycle.
    if (static_cast<int>(order.size()) != numCourses) return {};
    return order;
}

bool canFinish(int numCourses,
               const std::vector<std::vector<int>>& prerequisites) {
    return static_cast<int>(findOrder(numCourses, prerequisites).size())
           == numCourses;
}

4.2 Complexity

Time O(V + E)

O(V+E) to build the graph, then each node is enqueued and dequeued exactly once and each edge is relaxed exactly once. At V = 2000, E = 5000 that is ~7000 steps — microseconds.

Space O(V + E)

Adjacency list O(V+E), in-degree array O(V), queue O(V), output O(V). No recursion, so no stack risk at any V.

Edge cases this version already handles

Self-loop [[0,0]] → indeg[0] = 1 forever, order is short, returns false. Duplicate edges → counted twice, decremented twice, still correct. Disconnected components → all covered by the multi-source seed. prerequisites = [] → every node seeds the queue, order is [0,1,…]. numCourses = 0 → empty order, 0 == 0, true.

4.3 Variant: DFS three-colour cycle detection

The same O(V+E), reached from the other direction. Colour every node WHITE (unvisited), GRAY (on the current DFS path) or BLACK (fully explored, proven safe). Entering a node paints it GRAY; finishing it paints it BLACK. If DFS ever reaches a GRAY node, that edge closes a loop back onto the current path — a back edge — and the graph has a cycle.

Why two colours are not enough

With a single visited boolean you cannot tell “I am currently inside this node's exploration” from “I finished this node earlier down another branch.” The first is a cycle; the second is an ordinary shared dependency (node 3 in the diamond example, reached from both 1 and 2). A two-state check reports a cycle on the diamond, which is wrong. This is the classic bug in this problem.

from typing import List

WHITE, GRAY, BLACK = 0, 1, 2


def can_finish_dfs(num_courses: int, prerequisites: List[List[int]]) -> bool:
    """DFS three-colour cycle detection. True iff the graph is a DAG.

    Recursion depth is O(V); safe at V = 2000, convert to an explicit
    stack if V can reach 10^5 or more.
    """
    adj: List[List[int]] = [[] for _ in range(num_courses)]
    for course, prereq in prerequisites:
        adj[prereq].append(course)

    color = [WHITE] * num_courses

    def acyclic_from(node: int) -> bool:
        if color[node] == GRAY:
            return False                   # back edge: cycle on this path
        if color[node] == BLACK:
            return True                    # explored before, already safe

        color[node] = GRAY                 # enter: node is on the path
        for nxt in adj[node]:
            if not acyclic_from(nxt):
                return False
        color[node] = BLACK                # leave: node fully explored
        return True

    # Every node needs its own start -- disconnected components again.
    return all(acyclic_from(c) for c in range(num_courses))
const WHITE: u8 = 0;
const GRAY: u8 = 1;
const BLACK: u8 = 2;

/// Returns false as soon as a back edge (edge into a GRAY node) is found.
fn acyclic_from(node: usize, adj: &[Vec<usize>], color: &mut [u8]) -> bool {
    match color[node] {
        GRAY => return false,              // back edge: cycle on this path
        BLACK => return true,              // explored before, already safe
        _ => {}
    }

    color[node] = GRAY;                    // enter: node is on the path
    for i in 0..adj[node].len() {
        if !acyclic_from(adj[node][i], adj, color) {
            return false;
        }
    }
    color[node] = BLACK;                   // leave: node fully explored
    true
}

/// DFS three-colour cycle detection. True iff the graph is a DAG.
pub fn can_finish_dfs(num_courses: usize, prerequisites: &[(usize, usize)]) -> bool {
    let mut adj: Vec<Vec<usize>> = vec![Vec::new(); num_courses];
    for &(course, prereq) in prerequisites {
        adj[prereq].push(course);
    }

    let mut color = vec![WHITE; num_courses];
    // Every node needs its own start -- disconnected components again.
    (0..num_courses).all(|c| acyclic_from(c, &adj, &mut color))
}
import java.util.ArrayList;
import java.util.List;

class Solution {

    private static final int WHITE = 0;
    private static final int GRAY = 1;
    private static final int BLACK = 2;

    /** DFS three-colour cycle detection. True iff the graph is a DAG. */
    public boolean canFinishDfs(int numCourses, int[][] prerequisites) {
        List<List<Integer>> adj = new ArrayList<>(numCourses);
        for (int i = 0; i < numCourses; i++) {
            adj.add(new ArrayList<>());
        }
        for (int[] pair : prerequisites) {
            adj.get(pair[1]).add(pair[0]);
        }

        int[] color = new int[numCourses];        // all WHITE (0)
        // Every node needs its own start -- disconnected components again.
        for (int c = 0; c < numCourses; c++) {
            if (!acyclicFrom(c, adj, color)) return false;
        }
        return true;
    }

    private boolean acyclicFrom(int node, List<List<Integer>> adj, int[] color) {
        if (color[node] == GRAY) return false;    // back edge: cycle
        if (color[node] == BLACK) return true;    // explored, already safe

        color[node] = GRAY;                       // enter: node on the path
        for (int nxt : adj.get(node)) {
            if (!acyclicFrom(nxt, adj, color)) return false;
        }
        color[node] = BLACK;                      // leave: fully explored
        return true;
    }
}

bool canFinishDfs(int numCourses,
                  const std::vector<std::vector<int>>& prerequisites) {
    std::vector<std::vector<int>> adj(numCourses);
    for (const auto& pair : prerequisites) {
        adj[pair[1]].push_back(pair[0]);
    }

    std::vector<int> color(numCourses, kWhite);
    // Every node needs its own start -- disconnected components again.
    for (int c = 0; c < numCourses; ++c) {
        if (!acyclicFrom(c, adj, color)) return false;
    }
    return true;
}
Time O(V + E)

Identical to Kahn's: each node is coloured once, each edge traversed once. BLACK acts as a memo so no subtree is re-explored.

Space O(V + E)

Adjacency plus the colour array — but also O(V) recursion stack. A path graph of 10⁵ nodes overflows the default stack; that is the reason to prefer Kahn's when V is large.

Which one would I ship?

Kahn's, by default: iterative, no stack limit, gives the ordering for free, and the “order too short” check is trivially auditable. DFS colouring wins when you need to report the offending cycle, because the GRAY nodes on the stack are the cycle — useful for an error message like “circular dependency: A → B → C → A”.

5. Follow-up discussion if time permits

  • Minimum number of semesters, unlimited courses per semester. Run Kahn's level by level: drain the entire queue as one semester before processing the next batch. The answer is the number of levels, which is the longest path in the DAG — still O(V+E).
  • At most k courses per semester. Now it is scheduling with a resource cap, and greedy-by-in-degree is no longer optimal in general (it is NP-hard for arbitrary precedence graphs). Good place to say “I would use a heuristic — prioritise courses with the longest downstream chain — and be explicit that it is a heuristic.”
  • Lexicographically smallest valid order. Replace the FIFO queue with a min-heap: O((V+E) log V). Note that this is a different problem and greedy-smallest-first is provably correct here only because any zero-in-degree node can legally go next.
  • Report the actual cycle, not just its existence. Use the DFS variant and, on finding a back edge into GRAY node x, unwind the recursion stack until you see x again. That slice is the cycle. This is what a build tool prints.
  • Count all valid topological orders. Exponential in general; DP over subsets gives O(2^V · V), which is only viable for V ≤ ~20. Worth stating the bound rather than attempting it.
  • Alien dictionary. Given words sorted in an unknown alphabet, derive edges from the first differing character of each adjacent word pair, then topologically sort the letters. The subtle part is not the sort — it is detecting the invalid input ["abc", "ab"], where a prefix follows its own extension.
  • Course Schedule III (deadlines and durations). Completely different: sort by deadline and use a max-heap to greedily drop the longest course whenever you overrun. Mention it so the interviewer knows you are not pattern-matching on the title.
  • Edges arrive incrementally — keep the order valid online. This is dynamic topological ordering; the practical answer is to maintain the order and locally repair the affected window on each insertion, rejecting an edge that would close a cycle. Real systems (incremental build graphs) do exactly this.
  • The graph does not fit on one machine. Distributed BFS in the Pregel model: each vertex holds its in-degree counter and messages its dependents when it activates. Rounds = longest path length, which is why very deep DAGs are the pathological case.
  • What does “good enough” look like here? Confirm the edge direction before coding, state the DAG equivalence, give and discard the repeated-scan baseline, write Kahn's with the multi-source seed and the length check correct, trace the cyclic input to show the failure mode, and be able to explain in one sentence why DFS needs three colours rather than two.
