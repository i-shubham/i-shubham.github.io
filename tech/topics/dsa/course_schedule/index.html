Course schedule / cycle detection

Prereq graphs are cycle detection in a trench coat — Kahn’s algorithm and DFS colors both belong in your pocket.

60-minute agenda

How I'd open the discussion

I'd frame this as: we have a directed graph where an edge (a, b) means 'take a before b'. The question is whether a valid ordering exists — which is equivalent to asking whether the graph is a DAG. If there's a cycle, no valid ordering exists.

I know two clean approaches: Kahn's algorithm (BFS with in-degree tracking) and DFS with three-color marking. Kahn's is iterative and gives you the topological order as a side effect. DFS coloring is recursive and detects back edges. I'd ask which the interviewer prefers, but I'd default to Kahn's because it's easier to reason about in an interview without accidentally messing up recursion state.

Open questions worth asking

  • Do we just need boolean 'can finish' or the actual ordering?
  • Can there be self-loops (course requires itself)?
  • Are course IDs 0-indexed integers or arbitrary strings?
  • Can there be duplicate edges in the input?
  • What's the range of numCourses — thousands or millions?
  • Multiple valid orderings — return any one?
  • Are there disconnected components (courses with no prereqs at all)?
  • Should we handle the empty input (0 courses)?

Scope I'd lock first

  • In: detect cycle (can finish) + produce topological order if no cycle.
  • Out: minimum semesters / parallel scheduling unless follow-up.

Functional requirements

  • Input: numCourses (int), prerequisites (list of [course, prereq] pairs).
  • Output for Course Schedule I: boolean — can all courses be finished?
  • Output for Course Schedule II: list of courses in valid order, or [] if impossible.

Non-functional / rough numbers

Time

O(V + E) for both Kahn's and DFS — each node and edge visited once.

Space

O(V + E) for adjacency list + in-degree array or color array.

Capacity estimate (do this on the board)

Approach / design notes

Kahn's algorithm: build an adjacency list and an in-degree array. Seed a queue with all nodes whose in-degree is 0. Pop a node, append to result, decrement in-degree of all its neighbors. If a neighbor hits in-degree 0, add it to the queue. After the queue empties, if the result length equals numCourses, the graph is a DAG — otherwise there's a cycle.

DFS coloring: mark each node WHITE (unvisited), GRAY (in current DFS path), or BLACK (fully processed). When visiting a node, mark it GRAY. If we reach a GRAY neighbor, we've found a back edge — cycle. When all neighbors are done, mark BLACK. A node marked BLACK is safe and won't be revisited.

I prefer Kahn's for interviews because the invariant is simple: zero in-degree means all prereqs are satisfied. DFS coloring is elegant but the GRAY/BLACK state transitions confuse people under pressure.

Deep dive (spend 15–25 minutes here)

Example: numCourses=4, prerequisites=[[1,0],[2,0],[3,1],[3,2]]. Graph: 0→1, 0→2, 1→3, 2→3.

Kahn's: in-degree = [0, 1, 1, 2]. Queue starts with [0] (only node with in-degree 0). Pop 0: result=[0]. Neighbors 1,2: in-degree becomes [0,0,0,2]. Enqueue 1 and 2. Pop 1: result=[0,1]. Neighbor 3: in-degree[3]=1. Not zero yet. Pop 2: result=[0,1,2]. Neighbor 3: in-degree[3]=0. Enqueue 3. Pop 3: result=[0,1,2,3]. Queue empty. len(result)=4 == numCourses. Valid ordering.

Now add a cycle: prerequisites=[[1,0],[0,1]]. Graph: 0→1, 1→0. in-degree = [1, 1]. No node has in-degree 0. Queue starts empty. Result is []. len(result)=0 != 2. Cycle detected.

DFS coloring on the cycle case: visit 0, mark GRAY. Visit neighbor 1, mark GRAY. Visit neighbor 0 — it's GRAY. Back edge found. Return False immediately.

Kahn's algorithm — can_finish + find_order

from collections import deque
from typing import List


def can_finish(num_courses: int, prerequisites: List[List[int]]) -> bool:
    """Kahn's algorithm (BFS topological sort).
    Returns True if all courses can be completed (i.e., no cycle)."""
    adj = [[] for _ in range(num_courses)]
    indeg = [0] * num_courses
    for course, prereq in prerequisites:
        adj[prereq].append(course)
        indeg[course] += 1

    # Seed the queue with all zero-indegree nodes
    queue = deque(i for i in range(num_courses) if indeg[i] == 0)
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for nei in adj[node]:
            indeg[nei] -= 1
            if indeg[nei] == 0:
                queue.append(nei)

    # If we processed all nodes, the graph is acyclic
    return len(order) == num_courses


def find_order(num_courses: int, prerequisites: List[List[int]]) -> List[int]:
    """Same BFS topo-sort but returns the valid ordering, or [] if a cycle exists."""

use std::collections::VecDeque;

/// Kahn's BFS topological sort.
/// Returns true if all courses can be completed (no cycle).
fn can_finish(num: usize, prereqs: &[(usize, usize)]) -> bool {
    let mut adj = vec![Vec::new(); num];
    let mut indeg = vec![0u32; num];
    for &(course, pre) in prereqs {
        adj[pre].push(course);
        indeg[course] += 1;
    }
    // Seed queue with zero-indegree nodes
    let mut queue: VecDeque<usize> = (0..num).filter(|&i| indeg[i] == 0).collect();
    let mut count = 0usize;
    while let Some(node) = queue.pop_front() {
        count += 1;
        for &nei in &adj[node] {
            indeg[nei] -= 1;
            if indeg[nei] == 0 { queue.push_back(nei); }
        }
    }
    count == num // all nodes processed ⇒ no cycle
}

/// Returns a valid course ordering, or empty Vec if a cycle exists.
fn find_order(num: usize, prereqs: &[(usize, usize)]) -> Vec<usize> {
    let mut adj = vec![Vec::new(); num];
    let mut indeg = vec![0u32; num];
    for &(course, pre) in prereqs {
        adj[pre].push(course);
        indeg[course] += 1;
    }
    let mut queue: VecDeque<usize> = (0..num).filter(|&i| indeg[i] == 0).collect();
    let mut order = Vec::with_capacity(num);
    while let Some(node) = queue.pop_front() {
        order.push(node);
        for &nei in &adj[node] {
            indeg[nei] -= 1;
            if indeg[nei] == 0 { queue.push_back(nei); }
        }
    }
    if order.len() == num { order } else { Vec::new() }
}
#import <Foundation/Foundation.h>
#include <vector>
#include <queue>

// Kahn's BFS topological sort
// Returns true if all courses can be completed (no cycle)
static bool canFinish(int numCourses,
                      const std::vector<std::pair<int,int>> &prereqs) {
    std::vector<std::vector<int>> adj(numCourses);
    std::vector<int> indeg(numCourses, 0);
    for (auto &[course, pre] : prereqs) {
        adj[pre].push_back(course);
        indeg[course]++;
    }
    // Seed queue with zero-indegree nodes
    std::queue<int> q;
    for (int i = 0; i < numCourses; i++)
        if (indeg[i] == 0) q.push(i);
    int count = 0;
    while (!q.empty()) {
        int node = q.front(); q.pop();
        count++;
        for (int nei : adj[node])
            if (--indeg[nei] == 0) q.push(nei);
    }
    return count == numCourses;
}

// Returns valid ordering as NSArray, or empty array if cycle exists
static NSArray<NSNumber *> *findOrder(int numCourses,
                                       const std::vector<std::pair<int,int>> &prereqs) {
    std::vector<std::vector<int>> adj(numCourses);
    std::vector<int> indeg(numCourses, 0);
    for (auto &[course, pre] : prereqs) {
        adj[pre].push_back(course);
        indeg[course]++;
    }
    std::queue<int> q;
    for (int i = 0; i < numCourses; i++)
        if (indeg[i] == 0) q.push(i);
    NSMutableArray *order = [NSMutableArray new];
    while (!q.empty()) {
        int node = q.front(); q.pop();
        [order addObject:@(node)];
        for (int nei : adj[node])
            if (--indeg[nei] == 0) q.push(nei);
    }
    return (int)order.count == numCourses ? order : @[];
}

Request path / sequence

Trade-offs I'd say out loud

Kahn's vs DFS

Kahn's gives ordering naturally; DFS needs post-order reversal.

Queue vs stack

Queue gives BFS level order; stack gives one valid DFS order — both correct.

Adjacency list vs matrix

List is O(V+E) space; matrix is O(V²) — list wins for sparse graphs.

Where it usually breaks

  • Reversing the edge direction (prereq → course vs course → prereq).
  • Forgetting disconnected components — nodes with no edges still need processing.
  • Self-loops not caught if you only check neighbor != current.
  • Using visited boolean instead of three colors in DFS — misses back edges.
  • Stack overflow on deep graphs with recursive DFS — use iterative for V > 10^4.

Follow-ups if time remains

  • Course Schedule III — minimum semesters = longest path in the DAG (BFS level counting).
  • Parallel course scheduling — how many courses can we take simultaneously each semester?
  • Alien dictionary — derive ordering from sorted word list, then topological sort.
  • Detect all cycles, not just one — DFS coloring with back-edge collection.

What "good enough" looks like in 60 minutes

Cleanly model the graph, implement Kahn's with correct edge direction, trace through a cycle example showing the in-degree never hits zero, and explain DFS coloring as an alternative. Mentioning the alien dictionary connection shows you see the pattern, not just the problem.
