Merge k sorted lists

k-way merge shows up in external sort and in interview rooms — the heap is the point, not list pointer gymnastics.

60-minute agenda

How I'd open the discussion

I'd open with three approaches side by side: naive pairwise merge, divide-and-conquer, and min-heap. Pairwise looks fine until you realize each merge pass touches all N total nodes, and you do k-1 passes — that's O(kN) total work. Divide-and-conquer cuts it to O(N log k) by halving the number of lists each round, like merge sort on the list array.

The min-heap approach also gets O(N log k): maintain a heap of size k with one element from each list. Pop the min, advance that list's pointer, push the next element. N pops, each costing O(log k). I'd lead with the heap because it's the approach that generalizes to streaming — external sort, merging sorted runs from disk — and that's the real-world context where this pattern earns its keep.

Open questions worth asking

  • Are all k lists individually sorted in ascending order?
  • Can individual lists be empty? Can k be 0?
  • Linked lists or arrays?
  • Duplicates across lists — preserve all or deduplicate?
  • Do we need stable merge (preserve order of equal elements)?
  • Memory: build a new list or reuse existing nodes?
  • Bounds on k and total N for complexity discussion?
  • Is this an in-memory problem or could lists be on-disk sorted runs?

Scope I'd lock first

  • In: merge k sorted linked lists into one sorted list, heap-based O(N log k).
  • Out: on-disk merge and parallel merge unless follow-up.

Functional requirements

  • Input: List[Optional[ListNode]] of k sorted linked lists.
  • Output: single merged sorted linked list head.
  • Preserve all duplicates in sorted order.

Non-functional / rough numbers

Time

O(N log k) where N = total nodes across all lists.

Space

O(k) for the heap; O(1) extra if we reuse existing nodes.

k=0 or all empty

Return None without crashing.

Capacity estimate (do this on the board)

k=1, N=10^6

Just return the single list — O(N) pass-through.

k=10^4, N=10^6

Heap of 10^4 elements; each pop is ~14 comparisons.

k=10^6, N=10^6

Approach / design notes

Use a min-heap of size k. For each non-empty list, push (value, tiebreaker, node) into the heap. The tiebreaker is a counter to avoid comparing ListNode objects when values tie — Python 3 will throw TypeError if you try to compare custom objects without __lt__.

Create a dummy head node. Pop the smallest (val, _, node) from the heap, append node to the result tail. If node.next exists, push (node.next.val, counter, node.next). Repeat until the heap is empty.

Divide-and-conquer alternative: merge lists[0..k//2] and lists[k//2..k] recursively, then merge the two results. Base case: single list or empty. This avoids the heap import and is elegant, but less flexible for streaming scenarios where new sorted runs appear over time.

Pop (3,2,node3→3): result=[1,2,3]. Push (6,5,L3[1]). Heap: [(4,..), (5,..), (6,..)]. Pop (4,3,node1→4): result=[1,2,3,4]. Push (7,6,L1[2]). Heap: [(5,..), (6,..), (7,..)]. Pop (5,4,node2→5): result=[1,2,3,4,5]. Push (8,7,L2[2]). Heap: [(6,..), (7,..), (8,..)]. Pop (6,5,node3→6): result=[..6]. Push (9,8,L3[2]). Heap: [(7,..), (8,..), (9,..)]. Pop 7, 8, 9 — no more nexts. Result: [1,2,3,4,5,6,7,8,9].

9 pops, each O(log 3) ≈ 1.6 comparisons. Total ≈ 15 comparisons vs pairwise which would do two merge passes: merge L1+L2 (6 compares), then merge result+L3 (12 compares) = 18. Difference grows with larger k.

Min-heap k-way merge

import heapq
from typing import List, Optional


class ListNode:
    def __init__(self, val=0, nxt=None):
        self.val = val
        self.next = nxt


def merge_k_lists(lists: List[Optional[ListNode]]) -> Optional[ListNode]:
    """K-way merge using a min-heap.
    Counter breaks ties so heapq never compares ListNode objects."""
    heap: list = []
    counter = 0
    for head in lists:
        if head:
            heapq.heappush(heap, (head.val, counter, head))
            counter += 1

    dummy = tail = ListNode(0)
    while heap:
        val, _, node = heapq.heappop(heap)
        tail.next = node
        tail = tail.next
        if node.next:
            # Push the next element from the same list
            heapq.heappush(heap, (node.next.val, counter, node.next))
            counter += 1

    return dummy.next
use std::cmp::{Ordering, Reverse};
use std::collections::BinaryHeap;

#[derive(Clone)]
struct ListNode { val: i32, next: Option<Box<ListNode>> }

// Wrapper for BinaryHeap: Reverse gives us a min-heap by value
struct HeapEntry(i32, usize, Box<ListNode>);
impl PartialEq for HeapEntry { fn eq(&self, o: &Self) -> bool { self.0 == o.0 } }
impl Eq for HeapEntry {}
impl PartialOrd for HeapEntry {
    fn partial_cmp(&self, o: &Self) -> Option<Ordering> { Some(self.cmp(o)) }
}
impl Ord for HeapEntry {
    // Reversed so BinaryHeap (max-heap) acts as min-heap
    fn cmp(&self, o: &Self) -> Ordering {
        o.0.cmp(&self.0).then(o.1.cmp(&self.1))
    }
}

fn merge_k_lists(lists: Vec<Option<Box<ListNode>>>) -> Option<Box<ListNode>> {
    let mut heap = BinaryHeap::new();
    for (i, head) in lists.into_iter().enumerate() {
        if let Some(node) = head {
            heap.push(HeapEntry(node.val, i, node));
        }
    }
    let mut dummy = Box::new(ListNode { val: 0, next: None });
    let mut tail = &mut dummy;
    let mut counter = heap.len();
    while let Some(HeapEntry(_, _, mut node)) = heap.pop() {
        // Take ownership of the rest of the list
        let rest = node.next.take();
        tail.next = Some(node);
        tail = tail.next.as_mut().unwrap();
        if let Some(next) = rest {
            counter += 1;
            heap.push(HeapEntry(next.val, counter, next));
        }
    }
    dummy.next
}
#import <Foundation/Foundation.h>
#include <vector>
#include <queue>

struct ListNode {
    int val;
    ListNode *next;
    ListNode(int v = 0, ListNode *n = nullptr) : val(v), next(n) {}
};

// Min-heap comparator: smallest value has highest priority
struct Cmp {
    bool operator()(ListNode *a, ListNode *b) { return a->val > b->val; }
};

// K-way merge using a min-heap — O(N log K) total
static ListNode *mergeKLists(std::vector<ListNode *> &lists) {
    std::priority_queue<ListNode *, std::vector<ListNode *>, Cmp> heap;
    for (auto *head : lists)
        if (head) heap.push(head);

    ListNode dummy;
    ListNode *tail = &dummy;
    while (!heap.empty()) {
        ListNode *node = heap.top();
        heap.pop();
        tail->next = node;
        tail = tail->next;
        if (node->next)
            heap.push(node->next); // push next element from same list
    }
    return dummy.next;
}

// Convenience: wrap result as NSArray of values for easy inspection
static NSArray<NSNumber *> *mergedValues(std::vector<ListNode *> &lists) {
    ListNode *head = mergeKLists(lists);
    NSMutableArray *result = [NSMutableArray new];
    while (head) {
        [result addObject:@(head->val)];
        head = head->next;
    }
    return result;
}

Request path / sequence

Trade-offs I'd say out loud

Heap vs D&C

Heap is online-friendly (can add new lists); D&C needs all lists upfront.

Counter tiebreaker

Avoids TypeError on equal values; monotonic counter is cheaper than wrapping nodes.

Reuse vs copy

Reusing nodes saves memory but mutates input lists — clarify with interviewer.

Where it usually breaks

  • Comparing ListNode objects directly in Python 3 without a tiebreaker.
  • Forgetting to check if a list head is None before pushing.
  • Not advancing the pointer — infinite loop pushing the same node.
  • Off-by-one on divide-and-conquer base case (empty vs single list).
  • Memory leak if building new nodes instead of relinking existing ones.

Follow-ups if time remains

  • Merge k sorted arrays — same heap idea, use (val, array_idx, element_idx).
  • External sort — merge sorted runs from disk; heap of file iterators.
  • Merge with deduplication — skip if popped value equals last appended.
  • Parallel merge — split k lists across threads, merge results.

What "good enough" looks like in 60 minutes

Explain why pairwise merge is O(kN) and why heap or D&C is O(N log k). Write clean heap code with the counter tiebreaker, trace through a 3-list example, and mention the external-sort generalization. That covers the algorithm, the engineering, and the real-world application.
