Minimum window substring

The sliding window turned inside out: grow until valid, then shrink while still valid. Counting duplicates correctly is the whole problem.

1. Problem statement & explanation

Given two strings s (length m) and t (length n), return the shortest substring of s that contains every character of t, including duplicates. If no such substring exists, return the empty string "". The test cases are generated so that the answer is unique.

Two words carry all the weight. “Substring” means contiguous, so the answer is a window [left, right] rather than a scattered selection. “Including duplicates” means containment is multiset containment, not set containment: if t = "AABC" the window needs two separate 'A's, and one 'A' is not enough. Candidates who reach for a set here fail on exactly that case.

Note what the problem does not say: the window may freely contain characters that are not in t at all, and may contain more copies of a character than t requires. Validity is a lower bound on counts, never an equality. So the condition is: for every character c, countwindow(c) ≥ countt(c).

The structural property that makes a linear solution possible is monotonicity of validity in the window width: if [left, right] is valid, then [left, right'] is also valid for every right' > right — widening never removes a character. Equivalently, for each left there is a threshold right at which the window first becomes valid, and that threshold is non-decreasing as left advances. That is precisely the condition under which two pointers that only move forward suffice.

1.1 Input / output

Signature

contract
min_window(s: str, t: str) -> str   # the substring itself, "" when impossible

Worked examples

Example 1 — the standard case 
Input:  s = "ADOBECODEBANC", t = "ABC"
Output: "BANC"
Why:    "BANC" (indices 9..12) holds one 'A', one 'B', one 'C' in 4 characters.
        "ADOBEC" is also valid but is 6 long; "ODEBANC" is valid but 7 long.
Example 2 — the whole string is the answer 
Input:  s = "a", t = "a"
Output: "a"
Why:    the only substring that works is all of s.
Example 3 — impossible, and duplicates are why 
Input:  s = "a", t = "aa"
Output: ""
Why:    t needs TWO 'a's. s has one. A set-based check would wrongly say
        "a" is valid — this example exists to catch exactly that bug.
Example 4 — duplicates in t are counted, not deduped 
Input:  s = "ADOBECODEBANC", t = "ABCC"
Output: "CODEBANC"
Why:    now TWO 'C's are needed, so the window must span C at index 5
        through C at index 12. The answer for t = "ABC" ("BANC") is invalid here.
Example 5 — the window may carry surplus characters 
Input:  s = "aabbcc", t = "abc"
Output: "abbc"
Why:    indices 1..4. It contains an EXTRA 'b' that t never asked for.
        That is legal: validity is count(window) ≥ count(t), not equality.
Example 6 — case is significant 
Input:  s = "aAbB", t = "Ab"
Output: "Ab"
Why:    indices 1..2. 'a' does not satisfy 'A'. Both cases are in the alphabet,
        so the character table needs room for all 52 letters (128 is simpler).
Example 7 — why the problem guarantees uniqueness 
Input:  s = "ABAACBAB", t = "AABC"
        Minimum length is 4, and THREE different windows achieve it:
          indices 1..4 -> "BAAC"
          indices 2..5 -> "AACB"
          indices 3..6 -> "ACBA"
This input violates the "answer is unique" promise, so it will not be tested —
but you should still know what your code does. The solutions below use a
strict < when updating the best window, so they return the LEFTMOST: "BAAC".
Example 8 — degenerate inputs 
Input:  s = "xyz",  t = "a"    -> ""      (character absent entirely)
Input:  s = "ab",   t = "b"    -> "b"     (answer is a suffix)
Input:  s = "abc",  t = "cba"  -> "abc"   (order in t is irrelevant)
Input:  s = "aa",   t = "aa"   -> "aa"
Input:  n > m                  -> ""      (cannot fit; answer immediately)

Constraints to state back

  • m == s.length, n == t.length, 1 ≤ m, n ≤ 10^5 — both strings are non-empty, so no empty-input special case is strictly required, though a guard costs nothing.
  • These limits rule out the brute force. At m = 10^5, an O(m²) scan is ~1010 character operations. The linear solution is not a nice-to-have here; it is the only thing that runs.
  • s and t consist of uppercase and lowercase English letters — so Σ = 52 and a fixed 128-slot table covers it. The space term is therefore O(1), not O(n).
  • The answer is guaranteed unique, so no tie-breaking rule is needed. State what your code does anyway (see example 7).
  • t may be longer than s, and t may contain characters absent from s. Both simply yield "".
  • Return the substring itself. Internally it is cheaper to track (best_start, best_len) and slice once at the very end — never build strings inside the loop.

2. Open questions & clarifications

  • Substring or subsequence? The single most important question. Contiguous gives the O(m) window below; a subsequence gives a completely different O(m·n) dynamic-programming problem (see section 5). Do not guess.
  • Do duplicates in t count separately? Confirm multiset semantics explicitly: “for t = "AABC" I need two 'A's in the window, correct?” This is the difference between a Counter and a set.
  • May the window contain characters not in t? Yes — but say it out loud, because it establishes that the test is ≥ on counts rather than equality.
  • Case-sensitive? Is "Ab" satisfied by "ab"? Given the stated alphabet, no — but confirming it fixes your table size at 52/128 rather than 26.
  • What is the alphabet? English letters → fixed array, O(1) space. Full Unicode → hash map, and the space term becomes O(min(n, Σ)).
  • Return the substring, its length, or its indices? Returning indices avoids an O(m) copy, which matters if the caller only needs the bounds.
  • Ties — leftmost, rightmost, or any? The problem promises uniqueness, so this is free to ask and shows you noticed the promise rather than relied on it.
  • Is s fully in memory, or streamed? The window only ever moves forward, so a stream works, but you cannot return a slice of a stream without buffering.
  • One t or many? If many different t are queried against one fixed s, per-character index lists become worth precomputing — a genuinely different design.
  • Expected sizes? If t is tiny and s is enormous, the filtered-index variant in section 5 is a real win. If both are large, the plain window is already optimal.

2.1 Suggestions to the candidate

  • Do not open with “this is a sliding window problem”. That is pattern recognition, not reasoning, and interviewers discount it heavily. Earn it: state that validity is monotone in width, therefore the first-valid right is non-decreasing in left, therefore two forward-only pointers suffice. Now the window is a conclusion rather than a guess.
  • Do not present the optimal solution first. Spend two minutes on the brute force. Here it pays a specific dividend: it exposes that moving from start i to i+1 only removes one character, which is exactly the insight the real solution is built on.
  • Use the constraints as evidence. Saying “m is 105, so O(m²) is 1010 and cannot pass — I need linear” shows you read the limits. Most candidates never mention them.
  • Nail down multiset semantics before writing any code. Reaching for a set and discovering the t = "aa" case ten minutes later reads as carelessness. One clarifying sentence prevents it.
  • Track a scalar, not a map comparison. The natural-but-slow instinct is to compare the whole count map against t’s at each step: that is O(Σ) per character and drags you to O(m·Σ). Maintaining one integer missing is the difference between a good and a mediocre answer — call it out as a deliberate choice.
  • Say the two-phase discipline out loud as you code it. “Expand right until valid; then contract left while still valid, recording the best.” Then keep to it. Mixing expansion and contraction logic is where off-by-ones breed.
  • Record the best window at the right moment. Inside the contraction loop, before evicting, the window is valid. Recording after the eviction is a real and common bug that silently returns a window one character too short.
  • Explain why counts are allowed to go negative. A negative need[c] means surplus, and surplus is exactly the signal that the leftmost character is evictable. Interviewers watch for whether you understand this or merely copied it.
  • Trace "ADOBECODEBANC" / "ABC" yourself after writing the code. Show that left never moves backwards and that the best window is replaced three times. Finding your own bug is a strong signal; having it found for you is not.
  • Quantify space precisely. “O(Σ), bounded by 128 for this alphabet, so effectively O(1)” is far better than a hand-waved “O(n) for the map”.

3. Brute-force approach

Fix every start index i and extend rightwards until the window first becomes valid. Because validity is monotone in width, the first valid j is the shortest window for that particular start — so we can stop scanning that start immediately and move on.

  1. Build need = character counts of t.
  2. For each start i: copy need into remaining, and set missing = n.
  3. Walk j = i, i+1, …. For c = s[j]: if remaining[c] > 0 this character satisfies a real requirement, so decrement missing. Then decrement remaining[c] regardless.
  4. When missing == 0 the window [i, j] is valid and minimal for this i — record its length if it beats the best, then break.
  5. Return the best window found, or "" if none ever became valid.
Say this while writing it

The fully naive version is O(m³): enumerate all O(m²) substrings and re-count each one in O(m + n). Counting incrementally as j advances, plus the monotonicity break, already brings that down to O(m²). Mention both so the interviewer sees you optimising deliberately rather than landing on something by luck.

3.1 Code — Python, Rust, Java, C++

from collections import Counter


def min_window_brute(s: str, t: str) -> str:
    """Every start index, extended until the window first becomes valid.

    Validity is monotone in width, so the FIRST valid j is the shortest
    window for that start -- hence the `break`.
    """
    m, n = len(s), len(t)
    if m == 0 or n == 0 or n > m:
        return ""                          # cannot possibly fit

    need = Counter(t)
    best_len = m + 1                       # sentinel: "no window found"
    best_start = 0

    for i in range(m):
        remaining = need.copy()            # rebuilt per start: the wasteful part
        missing = n                        # required chars not yet covered

        for j in range(i, m):
            ch = s[j]
            if remaining[ch] > 0:          # this char satisfies a REAL need
                missing -= 1
            remaining[ch] -= 1             # may go negative: surplus

            if missing == 0:               # first valid window from i
                if j - i + 1 < best_len:   # strict <: keep the LEFTMOST best
                    best_len = j - i + 1
                    best_start = i
                break                      # no shorter window starts at i

    if best_len == m + 1:
        return ""
    return s[best_start:best_start + best_len]

/// Every start index, extended until the window first becomes valid.
///
/// Operates on bytes: the constraints say English letters, so every
/// character is one ASCII byte and byte slicing is safe.
pub fn min_window_brute(s: &str, t: &str) -> String {
    let sb = s.as_bytes();
    let tb = t.as_bytes();
    let (m, n) = (sb.len(), tb.len());
    if m == 0 || n == 0 || n > m {
        return String::new();              // cannot possibly fit
    }

    let mut need: HashMap<u8, i32> = HashMap::new();
    for &b in tb {
        *need.entry(b).or_insert(0) += 1;
    }

    let mut best_len = m + 1;              // sentinel: "no window found"
    let mut best_start = 0usize;

    for i in 0..m {
        let mut remaining = need.clone();  // rebuilt per start: the wasteful part
        let mut missing = n as i32;

        for j in i..m {
            let slot = remaining.entry(sb[j]).or_insert(0);
            if *slot > 0 {                 // satisfies a REAL need
                missing -= 1;
            }
            *slot -= 1;                    // may go negative: surplus

            if missing == 0 {
                if j - i + 1 < best_len {  // strict <: keep the LEFTMOST best
                    best_len = j - i + 1;
                    best_start = i;
                }
                break;                     // no shorter window starts at i
            }
        }
    }

    if best_len == m + 1 {
        String::new()
    } else {
        s[best_start..best_start + best_len].to_string()
    }
}

import java.util.Map;

class Solution {

    /**
     * Every start index, extended until the window first becomes valid.
     * Validity is monotone in width, so the first valid j is the shortest
     * window for that start -- hence the break.
     */
    public String minWindowBrute(String s, String t) {
        final int m = s.length(), n = t.length();
        if (m == 0 || n == 0 || n > m) {
            return "";                             // cannot possibly fit
        }

        Map<Character, Integer> need = new HashMap<>();
        for (char c : t.toCharArray()) {
            need.merge(c, 1, Integer::sum);
        }

        int bestLen = m + 1;                       // sentinel: none found
        int bestStart = 0;

        for (int i = 0; i < m; i++) {
            // Rebuilt per start: the wasteful part.
            Map<Character, Integer> remaining = new HashMap<>(need);
            int missing = n;

            for (int j = i; j < m; j++) {
                char c = s.charAt(j);
                int have = remaining.getOrDefault(c, 0);
                if (have > 0) {                    // satisfies a REAL need
                    missing--;
                }
                remaining.put(c, have - 1);        // may go negative: surplus

                if (missing == 0) {
                    if (j - i + 1 < bestLen) {     // strict <: LEFTMOST best
                        bestLen = j - i + 1;
                        bestStart = i;
                    }
                    break;                         // nothing shorter starts at i
                }
            }
        }

        return bestLen == m + 1 ? "" : s.substring(bestStart, bestStart + bestLen);
    }
}

    int bestStart = 0;

3.2 Complexity

Time O(m² + m·Σ)

Each of m starts scans up to m characters at O(1) each, plus an O(Σ) table copy per start. At m = 10^5 that is around 1010 operations — comfortably too slow, which is the point.

Space O(Σ)

Two count tables of at most 128 slots, independent of m and n. The brute force is not wasteful in memory — only in time.

Why this is not the final answer

When the window from start i first becomes valid at j, moving to start i+1 discards remaining and rescans [i+1, j] from scratch — but the only actual difference between the two windows is that s[i] left. Incrementing one counter recovers that in O(1). Do that instead of rebuilding, and left and right each traverse s exactly once.

4. Optimised approach

Key insight: maintain one window plus two pieces of bookkeeping. need[c] is how many further copies of c the window still requires — it goes negative when the window holds a surplus. missing is a single integer: the total number of required copies not yet covered. The window is valid exactly when missing == 0, which is an O(1) test rather than an O(Σ) map comparison.

The loop is then two alternating phases. Expand right one character at a time until the window becomes valid. Once valid, contract from the left as far as validity allows, recording the best window before each eviction. When contraction breaks validity, resume expanding. Neither pointer ever moves backwards.

  1. If n > m, return "" immediately — nothing can fit.
  2. need = character counts of t; missing = n; left = 0; best_len = ∞.
  3. Expand. For right = 0 … m-1 with c = s[right]: if need[c] > 0, this copy satisfies a real requirement, so missing -= 1. Then need[c] -= 1 unconditionally.
  4. Contract. While missing == 0: record [left, right] if it beats best_len; then evict lc = s[left] by need[lc] += 1, and if need[lc] > 0 we just gave back a genuinely needed character, so missing += 1; advance left.
  5. Return s[best_start : best_start + best_len], or "" if best_len was never set.
The invariants to say out loud

(a) need[c] = countt(c) - countwindow(c), for every character, at all times. (b) missing = the sum of need[c] over only those c where it is still positive — so missing == 0 if and only if the window is valid. (c) When the contraction loop exits, [left, right] is the shortest valid window ending at right, if one exists. Since the answer is some window ending at some right, taking the minimum over all right is exhaustive. (d) left is non-decreasing, so the two pointers together perform at most 2m steps.

The two subtleties interviewers probe

Why the need[c] > 0 guard before decrementing? Because only a character the window still needs represents progress. Without the guard, a surplus 'A' would also decrement missing and the window would be declared valid too early.

Why let counts go negative? The sign is the eviction test. need[lc] < 0 before eviction means the window holds a surplus of lc, so removing it keeps the window valid; the count rises to 0 and missing is untouched. Only when the count rises above 0 have we removed something required, and validity genuinely breaks. That single comparison replaces re-checking the whole map.

4.1 Code — Python, Rust, Java, C++

from collections import Counter


def min_window(s: str, t: str) -> str:
    """Expand-then-contract window over a multiset of required characters.

    Invariants:
      need[c] == count_t(c) - count_window(c)        (negative == surplus)
      missing == sum of need[c] over c where need[c] > 0
                 so `missing == 0` <=> the window is valid
      left is non-decreasing
    """
    m, n = len(s), len(t)
    if m == 0 or n == 0 or n > m:
        return ""                              # cannot possibly fit

    need = Counter(t)                          # char -> copies still required
    missing = n                                # required copies not yet covered
    left = 0
    best_len = m + 1                           # sentinel: "no window found"
    best_start = 0

    for right, ch in enumerate(s):
        # ---- expand: absorb s[right] ----
        if need[ch] > 0:                       # satisfies a REAL requirement
            missing -= 1
        need[ch] -= 1                          # may go negative: surplus

        # ---- contract: while still valid, shrink from the left ----
        while missing == 0:
            # The window is valid HERE, so record before evicting anything.
            if right - left + 1 < best_len:    # strict <: keep LEFTMOST best
                best_len = right - left + 1
                best_start = left

            lc = s[left]
            need[lc] += 1
            if need[lc] > 0:                   # gave back a REQUIRED char
                missing += 1                   # ... so validity just broke
            left += 1

    if best_len == m + 1:
        return ""
    return s[best_start:best_start + best_len]

                need.put(lc, back);

                    missing++;                         // ... validity just broke
                }
                left++;
            }
        }

4.2 Complexity

Time O(m + n)

Every character is absorbed by right exactly once and evicted by left at most once, so the pointers perform at most 2m steps, each O(1). Building need costs O(n). The nested while does not make this quadratic — left never resets, which is the amortised argument to state explicitly.

Space O(Σ) = O(1)

One count table. Bounded by 128 for the stated alphabet, so constant; with a hash map it is O(min(n, Σ)). The output slice is O(answer length) and only allocated once, after the loop.

Edge cases this version already handles

n > m → "" from the guard. t containing a character absent from s → missing never reaches 0 → "". t = "aa" against s = "a" → "", because missing starts at 2. Surplus characters → evicted by the contraction loop. s == t → the whole string. Ties → leftmost, via the strict <.

4.3 Variant: flat table, O(1) space, no copying

Two upgrades the interviewer often asks for next. First, replace the hash map with a flat array indexed by character code: the alphabet is bounded, so this is strictly O(1) space and materially faster — no hashing, no allocation, no pointer chasing. Second, return the bounds [start, end) instead of a new string, so the caller decides whether to pay for a copy at all. The C++ version returns a std::string_view and the Rust version returns a borrowed &str, both genuinely zero-copy.

from typing import Tuple

ALPHABET = 128                                 # ASCII covers both letter cases


def min_window_bounds(s: str, t: str) -> Tuple[int, int]:
    """Same window on a flat table; returns [start, end) instead of a copy.

    Returns (0, 0) when no valid window exists -- an empty half-open range.
    Precondition: every character satisfies ord(ch) < ALPHABET.
    """
    m, n = len(s), len(t)
    if m == 0 or n == 0 or n > m:
        return (0, 0)

    need = [0] * ALPHABET                      # code point -> copies required
    for ch in t:
        need[ord(ch)] += 1

    missing = n
    left = 0
    best_len = m + 1
    best_start = 0

    for right in range(m):
        c = ord(s[right])
        if need[c] > 0:
            missing -= 1
        need[c] -= 1

        while missing == 0:
            if right - left + 1 < best_len:
                best_len = right - left + 1
                best_start = left

            lc = ord(s[left])
            need[lc] += 1
            if need[lc] > 0:
                missing += 1
            left += 1

    if best_len == m + 1:
        return (0, 0)
    return (best_start, best_start + best_len)
/// Same window on a flat 128-slot table, returning a BORROWED slice.
///
/// `None` means no valid window exists, which is more honest than an
/// empty string: `Some("")` would be ambiguous if t were ever empty.
/// Byte-indexed, so this is correct for the stated ASCII alphabet.
pub fn min_window_view<'a>(s: &'a str, t: &str) -> Option<&'a str> {
    let sb = s.as_bytes();
    let tb = t.as_bytes();
    let (m, n) = (sb.len(), tb.len());
    if m == 0 || n == 0 || n > m {
        return None;
    }

    let mut need = [0i32; 128];                // byte value -> copies required
    for &b in tb {
        need[b as usize] += 1;
    }

    let mut missing = n as i32;
    let mut left = 0usize;
    let mut best_len = m + 1;
    let mut best_start = 0usize;

    for right in 0..m {
        let c = sb[right] as usize;
        if need[c] > 0 {
            missing -= 1;
        }
        need[c] -= 1;

        while missing == 0 {
            if right - left + 1 < best_len {
                best_len = right - left + 1;
                best_start = left;
            }

            let lc = sb[left] as usize;
            need[lc] += 1;
            if need[lc] > 0 {
                missing += 1;
            }
            left += 1;
        }
    }

    if best_len == m + 1 {
        None
    } else {
        Some(&s[best_start..best_start + best_len])
    }
}
class Solution {

    private static final int ALPHABET = 128;   // covers both letter cases

    /**
     * Same window on a flat table, returning bounds {start, end} rather
     * than a copy. Returns {0, 0} -- an empty range -- when none exists.
     * Precondition: every char is below ALPHABET.
     */
    public int[] minWindowBounds(String s, String t) {
        final int m = s.length(), n = t.length();
        if (m == 0 || n == 0 || n > m) {
            return new int[] {0, 0};
        }

        int[] need = new int[ALPHABET];        // code point -> copies required
        for (int i = 0; i < n; i++) {
            need[t.charAt(i)]++;
        }

        int missing = n;
        int left = 0;
        int bestLen = m + 1;
        int bestStart = 0;

        for (int right = 0; right < m; right++) {
            int c = s.charAt(right);
            if (need[c] > 0) {
                missing--;
            }
            need[c]--;

            while (missing == 0) {
                if (right - left + 1 < bestLen) {
                    bestLen = right - left + 1;
                    bestStart = left;
                }

                int lc = s.charAt(left);
                if (++need[lc] > 0) {
                    missing++;
                }
                left++;
            }
        }

        return bestLen == m + 1
                ? new int[] {0, 0}
                : new int[] {bestStart, bestStart + bestLen};
    }
}
#include <array>
#include <string>
#include <string_view>

// Same window on a flat table, returning a NON-OWNING view -- no copy.
//
// Caveat worth stating: the view borrows from `s`, so it dangles if `s`
// is a temporary. Taking string_view parameters makes that explicit.
std::string_view minWindowView(std::string_view s, std::string_view t) {
    const int m = static_cast<int>(s.size());
    const int n = static_cast<int>(t.size());
    if (m == 0 || n == 0 || n > m) {
        return {};                                     // empty view
    }

    std::array<int, 128> need{};
    for (char c : t) {
        ++need[static_cast<unsigned char>(c)];
    }

    int missing = n;
    int left = 0;
    int bestLen = m + 1;
    int bestStart = 0;

    for (int right = 0; right < m; ++right) {
        const auto c = static_cast<unsigned char>(s[right]);
        if (need[c] > 0) {
            --missing;
        }
        --need[c];

        while (missing == 0) {
            if (right - left + 1 < bestLen) {
                bestLen = right - left + 1;
                bestStart = left;
            }

            const auto lc = static_cast<unsigned char>(s[left]);
            if (++need[lc] > 0) {
                ++missing;
            }
            ++left;
        }
    }

    return bestLen == m + 1
            ? std::string_view{}
            : s.substr(bestStart, bestLen);
}
Time O(m + n)

Identical pass, minus the hashing and the per-character allocation. Typically 2–4× faster in practice on ASCII input.

Space O(Σ) = O(1)

A fixed 128-slot table regardless of input size, and zero output allocation — Rust and C++ return borrows, Python and Java return indices.

5. Follow-up discussion if time permits

  • “s is 106 characters but t is only 3. Can you do better?” Yes — the window wastes almost all its steps on irrelevant characters. Pre-filter s into a list of (index, char) pairs keeping only characters that appear in t, then slide over that list and compute widths from the stored original indices. Cost becomes O(m) for the filter plus O(k) for the window, where k is the number of relevant characters. Same asymptotics, but a large constant-factor win, and it is the natural answer to “what if t is tiny?”
  • Minimum window subsequence. Drop contiguity of the match (the window is still contiguous, but t must appear inside it in order, not merely by count) and the sliding window collapses — counts are no longer sufficient because order matters. It becomes an O(m·n) dynamic program, or a two-pointer forward/backward sweep. A good contrast to show you know why the window works here rather than just that it does.
  • Many queries against one fixed s. Precompute, for each character, the sorted list of its positions in s. Each query then works over only the relevant positions, which is a large win when the queried t use rare characters. Worth mentioning that this trades preprocessing memory O(m) for per-query speed.
  • Longest substring with at most k distinct characters / at most k replacements. The same two-pointer skeleton with a different predicate. Useful to name because it shows the pattern is a family: this problem is “shrink while valid”, those are “shrink while invalid”. Getting that direction backwards is the classic error.
  • Streaming s of unbounded length. The pointers only move forward, so the algorithm runs unchanged — but returning the substring requires retaining the current window, which is unbounded in the worst case. If only the length is needed, memory stays O(Σ).
  • Full Unicode input. Iterate over code points rather than bytes; a byte-indexed table silently mis-slices UTF-8. The table becomes a hash map and space rises to O(min(n, Σ)). If graphemes are the unit of comparison, segment first and run the same window over the cluster list.
  • Return every minimum-length window, not just one. Collect all windows achieving best_len rather than replacing on strict < (see example 7, which has three). Output is O(m) windows in the worst case, so ask whether they want them materialised or streamed.
  • Why can we not binary-search the answer length? Actually we can: “there exists a valid window of width w” is monotone in w, so a fixed-width scan per candidate w gives O(m log m). Strictly worse than O(m), but it is the right answer to “can you think of another approach?” and it demonstrates you spotted the monotonicity.
  • Weighted variant. If each character carries a cost and you must minimise total window cost rather than width, monotonicity breaks — a wider window can be cheaper — and the two-pointer argument fails entirely. Good probe for whether you know which property you were relying on.
  • What does “good enough” look like here? Confirm substring-not-subsequence and multiset-not-set, notice that m = 10^5 forbids the quadratic baseline, state and discard the brute force, write the window with the need[c] > 0 guard and the record-before-evict ordering both correct on the first attempt, give the amortised O(m + n) argument for why the nested loop is not quadratic, and quantify space as O(Σ) = O(1).
