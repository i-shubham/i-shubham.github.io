Serialize and deserialize a binary tree

The trick isn’t JSON — it’s preserving shape when nulls matter and leaves aren’t evenly balanced.

60-minute agenda

How I'd open the discussion

I'd say the hard part isn't picking a format — it's preserving the tree's shape including where nulls are. A BST can be reconstructed from preorder alone because the BST property constrains placement. A general binary tree can't — you need null markers or you lose structural information.

I'd discuss two approaches: preorder DFS with null markers, and level-order BFS with null markers. Both work, both are O(n). I'd default to preorder DFS because the code is shorter and the recursion mirrors how we think about trees. But if the interviewer cares about streaming or partial deserialization, level-order is better because you can reconstruct top-down without a stack.

Open questions worth asking

  • General binary tree or BST? (BST doesn't need null markers.)
  • Node values — integers, strings, can they contain the delimiter?
  • Any constraint on serialized format (JSON, custom string)?
  • Do we need to handle very deep trees (stack overflow concern)?
  • Single tree or a forest (multiple roots)?
  • Is the tree mutable after deserialization?
  • Compression — do we care about serialized size?
  • Should serialize → deserialize be a perfect round-trip?

Scope I'd lock first

  • In: serialize and deserialize a general binary tree with integer values.
  • Out: n-ary trees, BST-specific optimization unless follow-up.

Functional requirements

  • serialize(root) → string that encodes the full tree shape.
  • deserialize(data) → TreeNode root identical to original.
  • Round-trip: deserialize(serialize(tree)) produces a structurally identical tree.

Non-functional / rough numbers

Time

O(n) for both serialize and deserialize — visit each node once.

Space

O(n) for the output string; O(h) recursion stack for DFS, O(w) queue for BFS.

Null marker

Use a sentinel like '#' or 'null' that won't collide with valid values.

Capacity estimate (do this on the board)

n limit

up to 10^4 nodes in the LeetCode constraint

Depth limit

up to 10^4 — DFS recursion stack fits in most default limits (~10^4 frames)

String size

≤ 10^4 values + 2×10^4 nulls ≈ 30K tokens, each ≤ 5 chars → ~150 KB

BFS width

worst-case complete binary tree level has n/2 ≈ 5×10^3 nodes in queue

Approach / design notes

DFS preorder: visit root, write its value and a delimiter, recurse left, recurse right. For null children, write '#'. Example: tree [1, 2, 3, null, null, 4, 5] serializes to '1,2,#,#,3,4,#,#,5,#,#'.

Deserialize: split the string by delimiter into a list. Use an iterator (or index). Read the next token: if '#', return None. Otherwise create a node, recurse for left child, recurse for right child. The iterator naturally advances through the preorder sequence.

BFS level-order: use a queue. Enqueue root. For each node, write its value and enqueue children (writing '#' for null children but not enqueueing them). Deserialize by reading tokens in pairs for each non-null node's children.

The preorder DFS approach is more common in interviews because the recursive code is ~15 lines and the iterator trick is elegant. The BFS approach is more lines but easier to debug.

Deep dive (spend 15–25 minutes here)

Tree: 1 / \ 2 3 / \ 4 5

Serialize (preorder DFS): Visit 1 → write '1'. Go left. Visit 2 → write '2'. Go left → null → write '#'. Go right → null → write '#'. Back to 1. Go right. Visit 3 → write '3'. Go left. Visit 4 → write '4'. Left null → '#'. Right null → '#'. Back to 3. Go right. Visit 5 → write '5'. Left null → '#'. Right null → '#'. Result: '1,2,#,#,3,4,#,#,5,#,#'

Deserialize: tokens = ['1','2','#','#','3','4','#','#','5','#','#'], iterator at 0. Read '1' → create node(1). Recurse left: read '2' → node(2). Recurse left: read '#' → None. Recurse right: read '#' → None. Return node(2). Recurse right for node(1): read '3' → node(3). Recurse left: read '4' → node(4). Left '#'→None. Right '#'→None. Return node(4). Recurse right: read '5' → node(5). Left '#'→None. Right '#'→None. Return node(5). Return node(3). Return node(1). Tree reconstructed.

Edge case: empty tree → serialize returns '#'. Deserialize reads '#', returns None.

DFS preorder serialize / deserialize (Codec class)

from typing import Optional


class TreeNode:
    def __init__(self, val: int = 0, left=None, right=None):
        self.val = val
        self.left = left
        self.right = right


class Codec:
    """DFS preorder serialization.
    '#' marks null nodes so the tree can be reconstructed unambiguously."""

    def serialize(self, root: Optional[TreeNode]) -> str:
        tokens: list = []

        def dfs(node: Optional[TreeNode]) -> None:
            if not node:
                tokens.append("#")
                return
            tokens.append(str(node.val))
            dfs(node.left)
            dfs(node.right)

        dfs(root)
        return ",".join(tokens)

    def deserialize(self, data: str) -> Optional[TreeNode]:
        it = iter(data.split(","))

        def dfs() -> Optional[TreeNode]:
            tok = next(it)
            if tok == "#":
                return None
            node = TreeNode(int(tok))
            # Recursion order matches serialize: left first, then right
            node.left = dfs()
            node.right = dfs()
            return node

        return dfs()
use std::cell::RefCell;
use std::rc::Rc;

type TreeLink = Option<Rc<RefCell<TreeNode>>>;

struct TreeNode {
    val: i32,
    left: TreeLink,
    right: TreeLink,
}
impl TreeNode {
    fn new(val: i32) -> Rc<RefCell<Self>> {
        Rc::new(RefCell::new(Self { val, left: None, right: None }))
    }
}

/// DFS preorder: '#' marks null nodes for unambiguous reconstruction.
fn serialize(root: &TreeLink) -> String {
    let mut tokens = Vec::new();
    fn dfs(node: &TreeLink, out: &mut Vec<String>) {
        match node {
            None => out.push("#".to_string()),
            Some(rc) => {
                let n = rc.borrow();
                out.push(n.val.to_string());
                dfs(&n.left, out);
                dfs(&n.right, out);
            }
        }
    }
    dfs(root, &mut tokens);
    tokens.join(",")
}

fn deserialize(data: &str) -> TreeLink {
    let mut iter = data.split(',');
    fn dfs(it: &mut std::str::Split<char>) -> TreeLink {
        let tok = it.next()?;
        if tok == "#" { return None; }
        let node = TreeNode::new(tok.parse().ok()?);
        // Recursion order matches serialize: left, then right
        node.borrow_mut().left = dfs(it);
        node.borrow_mut().right = dfs(it);
        Some(node)
    }
    dfs(&mut iter)
}
#import <Foundation/Foundation.h>
#include <string>
#include <sstream>
#include <vector>

struct TreeNode {
    int val;
    TreeNode *left, *right;
    TreeNode(int v) : val(v), left(nullptr), right(nullptr) {}
};

// DFS preorder: '#' marks null nodes for unambiguous reconstruction
static std::string serialize(TreeNode *root) {
    std::string out;
    std::function<void(TreeNode *)> dfs = [&](TreeNode *node) {
        if (!node) { out += "#,"; return; }
        out += std::to_string(node->val) + ",";
        dfs(node->left);
        dfs(node->right);
    };
    dfs(root);
    if (!out.empty()) out.pop_back(); // remove trailing comma
    return out;
}

static TreeNode *deserialize(const std::string &data) {
    std::istringstream ss(data);
    std::string tok;
    // Recursive DFS mirrors the serialize order: val, left, right
    std::function<TreeNode *()> dfs = [&]() -> TreeNode * {
        if (!std::getline(ss, tok, ',') || tok == "#")
            return nullptr;
        TreeNode *node = new TreeNode(std::stoi(tok));
        node->left = dfs();
        node->right = dfs();
        return node;
    };
    return dfs();
}

// NSString convenience wrappers
static NSString *serializeTree(TreeNode *root) {
    return @(serialize(root).c_str());
}
static TreeNode *deserializeTree(NSString *data) {
    return deserialize(data.UTF8String);
}

Request path / sequence

Trade-offs I'd say out loud

DFS vs BFS

DFS is shorter code; BFS allows streaming top-down reconstruction.

String vs binary

Comma-separated string is human-readable; binary encoding is 2–3× smaller.

Null sentinel

'#' works for integers; for arbitrary strings, use length-prefixed encoding.

Where it usually breaks

  • Forgetting null markers — tree shape becomes ambiguous.
  • Using a global index instead of an iterator — off-by-one between recursive calls.
  • Delimiter collision if values can contain the delimiter character.
  • Stack overflow on very deep trees (10^5 depth) — switch to iterative DFS.
  • Not handling empty tree (serialize should return '#', not '').

Follow-ups if time remains

  • BST serialization without null markers — preorder is enough because BST property constrains reconstruction.
  • N-ary tree serialization — write child count before children, or use level-end markers.
  • Compact binary encoding — 1 bit per node for structure (1=node, 0=null) + values array.
  • Streaming deserialization — BFS allows you to reconstruct level by level as bytes arrive.
