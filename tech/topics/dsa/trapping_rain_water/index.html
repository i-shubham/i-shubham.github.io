Trapping rain water

Water at i is limited by the shorter of the tallest bars to the left and right — two pointers make that O(1) space.

60-minute agenda

How I'd open the discussion

I'd say the key insight is: water at position i equals min(max_left[i], max_right[i]) - height[i], clamped to zero. The brute force scans left and right for every i — O(n²). Precomputing prefix-max and suffix-max arrays brings it to O(n) time and O(n) space.

The real prize is the two-pointer approach: O(n) time and O(1) space. Start with pointers at both ends. Track left_max and right_max. If left_max <= right_max, the water at the left pointer is determined by left_max (the right side is at least as tall, so it's not the bottleneck). Process left and move inward. Otherwise process right. This works because we always process the side with the lower known max, and the other side can only be >= that — so we have enough information.

I'd draw the height array [0,1,0,2,1,0,1,3,2,1,2,1] and walk through both approaches before coding.

Open questions worth asking

  • Can heights be zero? Negative?
  • Is the array guaranteed non-empty?
  • Integer heights or floating-point?
  • Do we return total water or water at each position?
  • Array length — can it be 10^5 or 10^6?
  • Is this a 1D problem (elevation map) or 2D grid?
  • Any follow-up about trapping between buildings in 2D?
  • Do we count water on the edges (leftmost/rightmost bars)?

Scope I'd lock first

  • In: 1D trapping rain water, O(n) time O(1) space two-pointer solution.
  • Out: 2D trapping water (grid) unless follow-up; container with most water (different problem).

Functional requirements

  • Input: height[] — non-negative integer elevation map.
  • Output: total units of water trapped.
  • Edges cannot trap water (nothing beyond the boundary to hold it).

Approach / design notes

Prefix/suffix: left_max[i] = max(height[0..i]). right_max[i] = max(height[i..n-1]). Water at i = max(0, min(left_max[i], right_max[i]) - height[i]). Sum it up. O(n) time, O(n) space.

Two-pointer: lo=0, hi=n-1, left_max=0, right_max=0. While lo < hi: If height[lo] < height[hi]: If height[lo] >= left_max: update left_max. Else: water += left_max - height[lo]. lo++. Else: If height[hi] >= right_max: update right_max. Else: water += right_max - height[hi]. hi--.

Why the two-pointer works: when height[lo] < height[hi], we know right_max >= height[hi] > height[lo], so the water at lo is determined entirely by left_max. We don't need to know the exact right_max — we only need to know it's not the bottleneck. Symmetric argument for the other side.

Stack-based alternative: process bars left to right. For each bar, while it's taller than the stack top, pop the top (it's a valley), compute trapped water between the new top and current bar. This is O(n) time and O(n) space but harder to get right under pressure.

Two-pointer O(1) space + prefix/suffix O(n) space

from typing import List


def trap(height: List[int]) -> int:
    """Two-pointer O(1) space: converge from both ends,
    always advancing the side with the smaller max."""
    if not height:
        return 0
    lo, hi = 0, len(height) - 1
    left_max = right_max = 0
    water = 0
    while lo < hi:
        if height[lo] < height[hi]:
            if height[lo] >= left_max:
                left_max = height[lo]
            else:
                # Water trapped = left_max - current bar height
                water += left_max - height[lo]
            lo += 1
        else:
            if height[hi] >= right_max:
                right_max = height[hi]
            else:
                water += right_max - height[hi]
            hi -= 1
    return water


def trap_prefix_suffix(height: List[int]) -> int:
    """O(n) space variant: precompute left-max and right-max arrays,
    then water at each position = min(left_max, right_max) - height."""
    n = len(height)
    if n < 3:
        return 0
    left_max = [0] * n
    right_max = [0] * n
    left_max[0] = height[0]
    for i in range(1, n):
        left_max[i] = max(left_max[i - 1], height[i])
    right_max[-1] = height[-1]
    for i in range(n - 2, -1, -1):
        right_max[i] = max(right_max[i + 1], height[i])
    return sum(
        min(left_max[i], right_max[i]) - height[i]
        for i in range(n)
    )
/// Two-pointer O(1) space: converge from both ends,
/// always advancing the side with the smaller max.
fn trap(height: &[i32]) -> i32 {
    if height.is_empty() { return 0; }
    let (mut lo, mut hi) = (0usize, height.len() - 1);
    let (mut left_max, mut right_max) = (0i32, 0i32);
    let mut water = 0i32;
    while lo < hi {
        if height[lo] < height[hi] {
            if height[lo] >= left_max {
                left_max = height[lo];
            } else {
                water += left_max - height[lo]; // trapped between bars
            }
            lo += 1;
        } else {
            if height[hi] >= right_max {
                right_max = height[hi];
            } else {
                water += right_max - height[hi];
            }
            hi -= 1;
        }
    }
    water
}

/// O(n) space variant: precompute prefix-max and suffix-max arrays.
fn trap_prefix_suffix(height: &[i32]) -> i32 {
    let n = height.len();
    if n < 3 { return 0; }
    let mut left_max = vec![0i32; n];
    let mut right_max = vec![0i32; n];
    left_max[0] = height[0];
    for i in 1..n {
        left_max[i] = left_max[i - 1].max(height[i]);
    }
    right_max[n - 1] = height[n - 1];
    for i in (0..n - 1).rev() {
        right_max[i] = right_max[i + 1].max(height[i]);
    }
    // Water at each bar = min(left_max, right_max) - height
    (0..n).map(|i| left_max[i].min(right_max[i]) - height[i]).sum()
}
#import <Foundation/Foundation.h>
#include <vector>
#include <algorithm>

// Two-pointer O(1) space: converge from both ends
static int trap(const std::vector<int> &height) {
    if (height.empty()) return 0;
    int lo = 0, hi = (int)height.size() - 1;
    int leftMax = 0, rightMax = 0, water = 0;
    while (lo < hi) {
        if (height[lo] < height[hi]) {
            if (height[lo] >= leftMax) leftMax = height[lo];
            else water += leftMax - height[lo]; // trapped between bars
            lo++;
        } else {
            if (height[hi] >= rightMax) rightMax = height[hi];
            else water += rightMax - height[hi];
            hi--;
        }
    }
    return water;
}

// O(n) space: precompute prefix-max and suffix-max arrays
static int trapPrefixSuffix(const std::vector<int> &height) {
    int n = (int)height.size();
    if (n < 3) return 0;
    std::vector<int> leftMax(n), rightMax(n);
    leftMax[0] = height[0];
    for (int i = 1; i < n; i++)
        leftMax[i] = std::max(leftMax[i-1], height[i]);
    rightMax[n-1] = height[n-1];
    for (int i = n-2; i >= 0; i--)
        rightMax[i] = std::max(rightMax[i+1], height[i]);
    // Water at each bar = min(leftMax, rightMax) - height
    int water = 0;
    for (int i = 0; i < n; i++)
        water += std::min(leftMax[i], rightMax[i]) - height[i];
    return water;
}

// NSArray convenience wrapper
static NSInteger trapWater(NSArray<NSNumber *> *heights) {
    std::vector<int> h;
    for (NSNumber *n in heights) h.push_back(n.intValue);
    return trap(h);
}

Request path / sequence

Trade-offs I'd say out loud

Two-pointer vs prefix/suffix

Same O(n) time; two-pointer saves O(n) space but is harder to explain.

Proof of correctness

Two-pointer relies on 'shorter side determines water' — draw the argument if interviewer asks.

Stack approach

Processes valleys as units rather than columns — useful mental model for 2D extension.

Where it usually breaks

  • Off-by-one: processing lo == hi position (not needed, but forgetting causes double-count).
  • Updating max after computing water instead of before — gives wrong max for current position.
  • Confusing this with 'container with most water' — different problem, same two-pointer template.
  • Negative heights not handled (problem guarantees non-negative, but say it).
  • Empty array crash — check len(height) < 3 early.

Follow-ups if time remains

  • 2D trapping rain water — BFS from boundary inward with a min-heap of border heights.
  • Container with most water — two pointers, but max area instead of sum of trapped water.
  • Trapping rain water with holes — what if some bars have gaps? Changes the model.
  • Largest rectangle in histogram — related but different; monotonic stack pattern.
